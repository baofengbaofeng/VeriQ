# 本机暂存与磁盘运维

本指南说明首版保留可变暂存后的本机运维方式。实现依据为 [ADR 0031](../decisions/0031-可变暂存保留与磁盘准入.md)。
当前验证以 Linux 组件和相关纯单元测试为主，不代表 macOS、Windows 安装或完整桌面 GUI 已验收。

## 磁盘不足时的行为

Agent 在领取新任务前观察 Runtime 根目录、已存在工作父目录和实际暂存父目录所在卷。
每个相关卷默认至少需要 512MiB 普通用户可用空间。工作目录单独挂载时也会单独检查。
这是准入时的观察，不是磁盘预留或内核配额；运行中的单任务字节/文件监视器继续生效。

| 提示                              | 含义                                     | 操作者下一步                                         |
| --------------------------------- | ---------------------------------------- | ---------------------------------------------------- |
| `RUNTIME_STORAGE_LOW`             | 已确认某个相关卷低于空间下限，领取暂停   | 检查各相关卷，增加可用空间或安排人工处理             |
| `RUNTIME_STORAGE_UNAVAILABLE`     | 目录或卷容量无法可靠核验，领取暂停       | 检查挂载、访问权限和存储可用性，不按“容量足够”继续   |
| `RUNTIME_SCRATCH_CLEANUP_PENDING` | 已知历史任务的暂存未自动清理，需人工核对 | 先确认停止与目录归属，并保留规定证据；不直接批量删除 |

常驻 Agent 按十秒间隔发起复查，查询耗时另计。空间恢复后继续领取，待定请求仍使用原 UUID。
暂停期间可以停止在线领取；这不代表受阻的存储设备或底层系统查询已经恢复。
单次 `--once` 模式以固定诊断和非零退出结束，由调用方在处理存储后重新发起。
磁盘恢复不等于已确认历史暂存完成回收，人工核对提示不会因此自动清除。

## 查看状态

桌面工作台沿现有状态区显示暂停原因和暂存核对提示。停止控件仍然可用。
命令行通过原有本机控制通道读取状态；发行入口为 `veriq_cli`：

```sh
veriq_cli runtime status
veriq_cli runtime stop
```

源码开发环境可在仓库根使用对应入口；须选择与正在运行的 Agent 相同的配置目录和凭据模式：

```sh
pnpm --filter @veriq/runtime dev runtime status
pnpm --filter @veriq/runtime dev runtime stop
```

状态保留原有运行状态和 PID，并可附加暂停及暂存核对信息，不输出私有任务路径或系统错误原文。
状态中的 PID、窗口关闭或“已请求停止”单独均不能证明相关执行进程已物理停止。

## 人工回收流程

1. 停止新任务领取，确认当前任务的实际停止回执及平台范围。存在 `STOP_UNCONFIRMED`、
   `PROCESS_QUARANTINED` 或其他不确定状态时，先按人工恢复流程确认执行进程，不删除现场。
2. 由有权管理员确认主机访问、选中的 Runtime 配置、任务归属和实际目录身份。
   不能只凭 `veriq-a-*` 名称、目录年龄或日志中的任意路径判断可删除；也不能扫描整个系统暂存目录批量回收。
3. 先保留要求的报告、Trace、原始证据和故障材料。暂存可能含业务中间数据，应按受限测试资料管理，
   不把完整目录公开上传到工单或公共存储。
4. 在确认相关写入者已停用及目录归属后，由管理员安排回收。只处理已确认的任务暂存，
   不删除设备身份、保险库、可信签发者、发行目录、引擎或浏览器缓存，也不删除恢复证明来绕过隔离。
   无法确认的目录继续保留，可选择增加存储容量。
5. 重新检查各相关卷并刷新状态。常驻 Agent 可在下一次复查恢复领取；单次模式需重新发起。
   若仍显示领取过期或恢复未确认，保留原请求及现场，按诊断处理，不通过删除 `claim-request.json` 强行继续。

提示反映本机已经知道的处置事实，不证明文件现在仍然存在，也不证明人工操作完成了安全擦除。
操作系统或其他程序对临时目录的处理不属于 VeriQ 的自动回收承诺。
本版不提供绕过所有权确认的一键清理；后续若要恢复自动回收，须先证明排他存储边界并独立验收。

## 结果与清理状态

业务结果、fixture 清理、执行进程停止证明和本机暂存处置分别记录。
`OWNERSHIP_UNCONFIRMED` 不代表断言失败；空间不足也不能用来解除未知进程隔离。
历史 `.veriq-retired` 文件保留原始含义，不授权新一轮自动清理。
更多协议边界见[联网任务的证据与恢复](../公共契约.md#联网任务的证据与恢复)。
