# 前端组件接入指南

本指南面向接入 VeriQ 的业务前端开发者，使用 React 18 示例说明如何提供稳定定位、可观察界面状态和可核验的业务结果。DSL 与 API 定义见[公共契约](../公共契约.md)和[前端接入契约](../integration/前端接入契约.md)。

C06 提供由业务工程显式引入的[可复用组件源码](../../fixtures/integration/react18/)。交付时尚未执行组件的构建、浏览器或类型验证。

## 工程和可观察状态

使用现有 React18、Vite6、Tailwind3 工程。示例复用仓库已声明的 Radix Dialog、CVA、TanStack Query5、react-i18next、dnd-kit/core 和 DOMPurify；把源码放入客户已有工程并由该工程声明直接依赖，不在 VeriQ 根建立新的锁文件。`VeriqButton.tsx` 展示 ref/属性透传，`EmployeePanel.tsx` 展示表单、查询和 Portal，`KeyboardOrder.tsx` 展示正常键盘排序。

应用根提供 `QueryClientProvider`、已初始化的 i18next/react-i18next Provider，并载入 Tailwind3 样式；Vite 配置应代理真正业务 API 或使用生产同源反代。示例请求 `/employees`，使用当前正常业务会话；在 VeriQ 内置 HTTP_BEARER 适配器下由 SDK 对允许的 API origin 注入普通业务身份，组件不接收 fixture token。自身 SSO/MFA 集成仍由业务应用承担，不能把平台 Cookie 当成业务登录。

页面需要同时可观察：加载、空数据、提交中、提交失败、查询失败、成功提示、持久化列表。示例保存禁用按钮，mutation `retry:false`；成功后等待精确 query key 的真实 GET。若产品采用乐观更新，应提供保存中的可见状态，并在失败时撤销临时行、恢复原值和显示错误。乐观渲染和 toast 不能用于持久化通过结论。

## veriqId、记录与目录

锚点代表业务语义，例如 `employee.form`、`employee.row`，不使用类名、随机值、数组下标、翻译文字或请求时间戳。Key/veriqId 采用 `^[A-Za-z_][A-Za-z0-9_.-]*$` 且最多160字符。React `key={employee.id}` 只控制渲染协调，DOM 必须另加 `data-record-key={employee.id}`。

```tsx
<tr key={employee.id} veriq-id="employee.row" data-record-key={employee.id}>
    <td veriq-id="employee.name">{employee.name}</td>
</tr>
```

行键使用非秘密业务 id；不要放 token、tokenId、secretRef、密码、邮箱、原始业务姓名或个人数据。即便 tokenId 不是明文 token，也不应充当公开 veriqId、可访问 label 或截图业务标题；授权元数据页按原角色规则显示它，普通业务界面不扩散凭据标识。

[实际示例目录](../../fixtures/sample-workspace/assets/catalog.json)依次定义 page→form→input/button、page→table→row→name；row 自身匹配 `recordKey: "{{vars.employeeId}}"`，name 使用 row scope。SDK 匹配当前 DOM 的 `data-record-key`，不会自动滚动到尚未挂载的虚拟行。先通过真实搜索、分页或滚动渲染目标，再断言唯一性；禁止 `nth(0)` 掩盖重复匹配。目录作用域不能成环。

| 变化 | 目录应该怎样处理 | 真实验收 |
| --- | --- | --- |
| 排序 / 筛选 | 同一行仍使用原业务 id | 翻转顺序后定位同一对象 |
| 分页 / 虚拟列表 | scope 指向当前真实挂载容器 | 搜索/翻页后再定位，离屏不假装存在 |
| 页面重构 | 锚点语义稳定，DOM scope 更新后新发版本 | 旧 Run 保持冻结目录，新依赖重新编译 |
| 多个同类控件 | 用具体业务区域 scope | 未指定区域出现歧义时应失败 |
| 翻译 | veriqId 不变，role name 按环境语言固定 | en-US / zh-CN 各自受控预期 |

## Radix、CVA、asChild 和 Portal

`VeriqButton` 用 `forwardRef<HTMLButtonElement>`，把 ref、`data-*`、`aria-*`、disabled、onClick 等传到原生 button，CVA 只处理展示变体。不要额外用 div 包裹按钮作为 ref 目标，也不要吞掉 Radix 注入的事件。`Dialog.Trigger asChild` 与 `Dialog.Close asChild` 的 child 必须支持这些能力；避免渲染 button 内嵌 button。

Portal 的视觉位置不等于 DOM 位置。示例 `employee.dialog` 挂到 body 下，应在目录中作为独立根，而不是 `scope: employee.page`；`employee.dialog.close` 再以 dialog 为 scope。仅锚定 Trigger 无法代表弹层内容。验证打开、隐藏/卸载、Escape、初始焦点、Tab 顺序、关闭后回到 Trigger；多个弹层不能留下重复可见锚点。

```json
{
    "schemaVersion": "1.0",
    "elements": [
        {"key":"employee.dialog","locator":{"by":"veriqId","value":"employee.dialog"}},
        {"key":"employee.dialog.close","scope":"employee.dialog","locator":{"by":"veriqId","value":"employee.dialog.close"}}
    ]
}
```

## TanStack Query 和操作证据

Query key 包含业务范围（示例是 fixture code）；不同 Workspace、租户、筛选条件和记录标识均应进入适当 key。queryFn 使用 AbortSignal；切空间或退出时取消旧请求、移除所属缓存。mutation 不自动重试业务写入，超时先按业务键只读查询真实结果。后台 refetch 不应被误当成保存请求。

[完整 CASE](../../fixtures/sample-workspace/assets/case.json)在 click 前安装 POST `/employees` 观察器，并用 code/name 匹配本次输入；HTTP200、业务状态 CREATED、id 类型及提取关系分开表达。随后 reload，按实际 id 定位表格行；再通过 `eventually` 对 GET `/employees?code=...` 的 `/items/0/id` 做独立只读检查。JSON Pointer 使用 RFC6901，`/` 与 `~` 分别转义成 `~1`、`~0`。

| 层级 | 可证明什么 | 不能据此推导什么 |
| --- | --- | --- |
| 表单值 / 按钮状态 | 当前可交互状态 | 后端已提交 |
| 目标请求与响应 | 发出了关联写入，接口返回约定结果 | 页面缓存一定正确 |
| toast / 乐观行 | 客户端展示结果 | 数据持久化 |
| reload 后行值 | 新页面读取到业务值 | 异步所有副作用已完成 |
| 独立只读 GET / 最终一致 | 受限总时间内真实结果符合契约 | 无限等待后总会成功 |

观察窗口必须与需求一致：`UNTIL_ACTION_SETTLED` 仅覆盖该动作及 quietMs；要验证精确请求次数，用固定窗口和符合 Schema 的 expectedCount，不能宣称整个 Run 绝无重复请求。预期依据写需求/API/人工受控数据编号，不能从当前页面抓取“期望”再与自己比较。

## i18next、时间和键盘

测试环境发布固定 `locale`（如 en-US、zh-CN）和 IANA `timezone`（如 UTC、Asia/Shanghai），每次 Run 冻结这些值和真实应用 build SHA。i18next 应在业务页加载前完成对应语言初始化；固定预期包括错误文案、日期、金额、小数和排序语义。不得把当前系统时区或测试者个人语言当成默认真值。跨日、夏令时及空值日期按业务契约单独设计用例。

所有输入有 label；错误用 role=alert，状态用 role=status，按钮使用原生 disabled。正常表单支持 Tab、Shift+Tab、Enter 提交；弹层支持 Escape 和焦点恢复。`KeyboardOrder` 使用 dnd-kit/core 的 KeyboardSensor，Space/Enter开始、箭头移动、Space/Enter放下、Escape取消，行与 handle 同时有稳定身份。DSL 可用 `press` 驱动这些正常按键；必须在真实布局里验证放置目标及保存请求，刷新和 GET 确认服务端顺序，不能只检查动画 transform。排序回调 `persist(ids)` 由应用实现真实保存和查询，它不是现成的 demo 业务路由。

## DOMPurify 和不可信内容

`EmployeePanel` 把清洗后的富文本放在可信外层 `employee.description` 内，只允许明确展示标签和 href，并禁止富文本自带 data 属性，避免注入假 veriqId/recordKey 误导定位。不可为了测试保留 script、事件处理器或危险 URL；不要在清洗完成后重新拼接不可信 HTML。

验收需同时检查：允许的粗体/链接可见、script/onerror/javascript URL 被移除、注入的 veriq-id 不参与可信目录、键盘能访问合法链接。截图、Trace 可能包含业务输入，保留其受限证据权限和保留期；不要在 Console、DOM label 或页面 title 输出认证头。

## 变更交付

前端变更提交受影响锚点、实际 DOM scope、recordKey、接口和目录版本清单。先使用受控 demo 完成工具链，再在自己的正常角色与真实业务测试环境重复表单成功/失败、权限拒绝、后台请求竞争、重复行排序、Portal、键盘、两种语言和持久化回读。后续执行细目见[V06](../validation/tasks/端到端接入验收.md)，示例通过不替代客户接入验收。
