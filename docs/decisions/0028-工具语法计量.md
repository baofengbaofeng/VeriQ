# 0028 工具语法计量

- 状态：已实施并通过独立规格及质量审查（b92f53f）；路径格式Minor源码已由c97526e闭合，Linux工具回归通过，Windows目标验证仍开放。
- 日期：2026-11-18（Asia/Shanghai）。
- 计量入口：[Coding Standard](../../.agents/rules/coding-standard.md#3-注释中文)。

## 1. 背景

`/* @vite-ignore */` 是 Vite 消费的固定块标记，加入中文会改变工具识别行为。
此前正文审计将它视为普通说明并报告语言与长度问题；直接排除整行又会少算代码分母。
用户已选择按功能代码计量，而非改写依赖该标记的测试实现。

## 2. 决策

只有成熟解析器确认上下文、且有实际工具行为证据的固定语法，才可按功能代码计量。
仅接纳冻结 Vite 6.4.5 的独立块标记 `/* @vite-ignore */`。整个词元区分大小写，只允许在 `/*` 后和 `*/` 前有 JavaScript `\s` 空白，不允许附加正文。冻结的 TypeScript 5.9.3 AST 须确认该调用是动态 `import()`，且真实块注释完整位于首个实参的前导 trivia。普通 `import` 方法、类型导入和字符串等字面量不合格。
桥接器只给合格范围增加 `codeDirective: "vite-ignore"`，其余注释保持普通计量。任一文件语法检查失败时，整批拒绝输出可信区间或分类结果。
有效注释 C 不增加，非空代码 K 保留；其余注释继续中文、正文 40～120 字符及 120 显示列检查。
全仓严格大于 40% 的硬门禁、库存范围和失败关闭保持不变。

不新增依赖，不替换 TypeScript AST，不将排版器的宽泛 pragma 前缀变成计量豁免。
工具行为与计量验收证据见[V09 质量记录](../validation/tasks/V09-quality.md#固定工具语法计量已交付)。

## 3. 后果与替代方案

计量更贴近工具实际语义，但需要逐项维护可信上下文和行为测试；未来指令不能自动套用。
实际 Vite 合成转换只证明工具消费，不能推导原有浏览器测试执行路径也经过同一转换。

未采用给固定标记加入说明、跳过整文件或整行、扩大前缀白名单、降低覆盖率门槛的方案。
未采用改写浏览器契约测试以消除该工具标记的替代方案；用户明确选择保留功能代码语义。
