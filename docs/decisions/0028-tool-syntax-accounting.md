## 背景

`/* @vite-ignore */` 是 Vite 消费的固定块标记，加入中文会改变工具识别行为。
此前正文审计将它视为普通说明并报告语言与长度问题；直接排除整行又会少算代码分母。
用户已选择按功能代码计量，而非改写依赖该标记的测试实现。

## 决策

只有成熟解析器确认上下文、且有实际工具行为证据的固定语法，才可按功能代码计量。
首批闭合范围为冻结 Vite 6.4.5 的动态导入首实参前导标记，桥接器输出可选已知角色。
有效注释 C 不增加，非空代码 K 保留；其余注释继续中文、正文 40～120 字符及 120 显示列检查。
全仓严格大于 40% 的硬门禁、库存范围和失败关闭保持不变。

不新增依赖，不替换 TypeScript AST，不将排版器的宽泛 pragma 前缀变成计量豁免。
完整范围、坐标、批次失败和验收约束见规格。

## 后果与替代方案

计量更贴近工具实际语义，但需要逐项维护可信上下文和行为测试；未来指令不能自动套用。
实际 Vite 合成转换只证明工具消费，不能推导原有浏览器测试执行路径也经过同一转换。

未采用给固定标记加入说明、跳过整文件或整行、扩大前缀白名单、降低覆盖率门槛的方案。
未采用改写浏览器契约测试以消除该工具标记的替代方案；用户明确选择保留功能代码语义。
