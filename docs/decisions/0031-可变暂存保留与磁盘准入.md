# 0031 可变暂存保留与磁盘准入

状态：已选择（用户已批准；实现与验收分阶段进行，尚未全部完成）。日期：2026-11-19（Asia/Shanghai）。

## 背景

现有 Linux 退休逻辑在最后路径复核与文件句柄截断之间仍允许并发移动或增加链接。
私有目录、进程排空、固定 inode 与一次性许可均不能证明不存在其他同 UID 写入者。
写后再报告 `OWNERSHIP_UNCONFIRMED` 无法撤销已经对树外原件的截断。
[问题与证据](../validation/Linux暂存清理边界.md)记录了源码、既有故障测试以及本轮实际执行边界。

## 决策

用户已选择“保留现场，配套磁盘保护与人工回收”。

- 当前没有排他所有权证明，Linux 也暂停对这些可变任务树的自动破坏性退休；Windows/macOS 延续保留语义。
- 正常结束与启动恢复遵循相同规则，不截断或删除成员，不签发新的退休许可或完成回执。
- 停止未知/范围不符继续为 `STOP_UNCONFIRMED` 并隔离未知进程；停止已确认记 `OWNERSHIP_UNCONFIRMED`。
- `REPORT_RETAINED` 保持既有优先规则。历史文件及回执不改写，也不作为新清理的授权。
- 业务完成、真实停止证明、fixture 清理与本机暂存保留各自记录，不因保留暂存篡改业务结论。
- 领取新任务前检查根目录及实际暂存卷可用空间；容量不足或无法核验时暂停新领取，提供可见诊断与恢复指引。
- 原单任务字节/文件监视器继续生效。磁盘准入观察不是内核配额，不能阻止观察之后其他程序占用空间。
- 人工回收须在确认主机访问、目录归属和证据保留要求后进行，不由自动程序猜测删除系统临时目录。

不新增平台权限、系统服务或存储隔离依赖。未来若需要恢复自动回收，须另行证明排他存储边界并验收。

### 磁盘准入的工程默认

以下是协调者在已批准方向内的工程取值，不是用户原先指定的参数：

- Runtime 根卷、已存在工作父目录所在卷、实际暂存父目录所在卷各至少保留 512MiB 可用空间。
- 使用 Node `statfs` 的 `bavail * bsize`，按 bigint 计算。无法核验或指标异常时同样暂停。
- 宿主内部 `SupervisorOptions.minimumFreeBytes` 可明确设定正安全整数阈值；Job、Provider 和 renderer 不得覆盖。
- 低空间诊断为 `RUNTIME_STORAGE_LOW`，无法确认容量为 `RUNTIME_STORAGE_UNAVAILABLE`。
- 正常 Agent 使用既有 10 秒可取消轮询复查；空间恢复后继续。单次 `--once` 返回固定诊断并非零结束。
- 暂停时保留待定领取 UUID，不以磁盘状态创建替代 UUID、清空旧请求或解除未知进程隔离。

这些规则在 R06b 中实现和验证；单任务 64MiB/10,000 项监视器的既有默认不变。

## 后果与替代方案

保留方案避免自动破坏来源不确定的文件，但任务依赖、暂存和历史现场会累积，可能因磁盘保护暂停新任务。
无人值守部署需要容量监控与明确的人工处置责任；首版不承诺自动安全擦除这些可变树。

未选择仅增加路径复核、在写入后承认不确定，或把固定 inode 等同于任务树成员身份。
独立 mount namespace 本身也不排除其他挂载视图写入同一底层对象。
专用文件系统、分离 UID 或强制访问控制需要新的部署及平台设计，当前不将其作为已落地能力。
