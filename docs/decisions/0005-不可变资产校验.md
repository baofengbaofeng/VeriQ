# 0005 不可变资产校验

<a id="adr-0005--immutable-asset-validation-and-source-identity"></a>

- 状态：已接受的 T04 实现边界；编译器、身份注册表及经过验证的 Runtime 完成链路仍由后续任务交付。

## 1. 决策记录

八种资源共用相同的草稿修订、不可变版本与成功 Runtime 回执规则。首次创建目录、数据集、fixture 或环境时，不能依赖伪造的已发布 CASE。`AssetSnapshotV1.validationTarget` 标识候选资源、版本与修订，并允许 `entryCaseVersionIds` 为空。`CompiledAssetBundle.validationOnly: true` 要求入口列表为空，但仍须具备真实文件与固定依赖。执行快照和 TEST 清单固定 `caseVersionId`；可执行入口显式将该版本 ID 映射到文件路径。没有验证目标的普通执行快照及普通编译包仍须包含用例和入口。T05/T09 必须拒绝空 TEST 选择，不得将其报告为通过的运行。

服务端按 `veriq:{workspaceId}:{resourceId}:{revision}:{documentHash}`，使用 UUIDv5/NAMESPACE_URL 确定性分配候选 UUID；发布时沿用该 UUID。`documentHash` 与版本 `sha256` 对完整 `{kind, document}` 信封计算摘要。`sourceHash` 精确针对 `{schemaVersion, workspaceId, engineVersion, entryCaseVersionIds, assets}` 的 RFC8785/JCS 字节计算。服务端按版本 UUID 排序资产，并按字典顺序排序入口用例 UUID。每项资产包含资源/版本 ID、类型、文档及文档信封的 SHA-256。数组的冻结顺序属于身份的一部分，消费者不得重新排序。验证目标元数据、声明的源码摘要、job/run/attempt ID、机器路径及执行值均不参与该投影。发布后移除验证元数据不会改变源码身份；实际保留的清单原字节仍是签名边界。

Python 使用 `rfc8785==0.1.4`，Node/浏览器使用 `canonicalize==2.1.0`，两者均为 Apache-2.0。普通排序 Python JSON 与 JavaScript JSON.stringify 在浮点格式、负零及 UTF-16 键排序上存在差异。自研 JCS 会重复承担数值、Unicode 正确性及互操作风险，因此选用成熟实现；既有可移植 JSON 守卫与孤立代理字符检查限定两端共同输入域。共享向量覆盖数值及 Unicode 边界，两种语言验证同一源码摘要。面向浏览器的包只导出字节，不依赖 Node crypto/Buffer；调用方自行选择 SHA-256 API。锁文件固定版本，库存记录许可元数据，发行组装必须保留上游许可证原文。

`GET .../resources/{resourceId}/validation-preview` 为当前修订生成服务端推导的文档摘要、候选版本 ID、闭包源码摘要及引擎版本。`POST .../validate` 将提交的修订和摘要与最新权威闭包比较，持久化不可变快照/清单字节，并创建 QUEUED VALIDATE 任务。任务仍在唯一的 `veriq_jobs` 队列中；该接口不编译，也不伪造完成。成员、变更及发布检查都遵守现有安装级守卫事务锁序。ENVIRONMENT 写入要求 MANAGE_ENVIRONMENT，资源类型不可变。

认证适配器和凭据引用使用 `IdentityReferenceRegistry.require_role(session, scope, role)`，不查询资产版本。它必须在调用方事务中检查适配器版本、secretRef/version 关联、吊销状态、允许身份与 Workspace，且不返回秘密。默认实现拒绝无法解析的引用。草稿可保留结构合法但尚未解析的引用，验证和发布不能接受它们；T07 提供该注册表。

回执表示获批准的 **MANAGED** 编译 Runtime 已成功完成经验证的编译，并记录 Runtime ID、完成 Attempt ID、引擎版本、源码摘要及精确编译描述符摘要。发布要求保留的已完成任务/活动 Attempt、精确快照/清单、匹配的根资源/修订/源码，以及描述符中每个文件保留的摘要和长度。**摘要匹配不能证明任意可执行代码由获批准的编译器生成。** T08–T10 的唯一回执写入方还必须认证当前租约/fencing，确认分配的 Workspace/job/attempt/runtime，要求管理员批准的可信编译器及已批准的引擎/编译器/SDK/依赖锁，验证真实不可变产物，并原子记录成功完成。个人 USER_REGISTERED 令牌不足以满足要求。T04 没有生产回执写入方或 HTTP 回执创建路由；在完成上述集成前发布不可用。测试在该未完成边界显式植入来源及字节。

T12 在重新分发可执行编译文件前必须执行相同来源检查，保留精确字节、签名和锁文件完整性；不能将调用方声明的源码摘要作为编译器证明。队列领取、租约、容量与重试属于 T09；本任务不在 Python 服务端引入第二个调度器、租约循环或浏览器执行。

资源正文限制为 2 MiB 规范 UTF-8 字节；创建/草稿 HTTP 信封限制为 2 MiB + 4096 字节，其他 JSON 操作为 64 KiB，Tornado HTTP 传输为 3 MiB。依赖闭包限制为 1000 项资产、深度 100、16 MiB 规范字节。二进制流式传输与保留期属于 T12。列表使用既有签名游标，绑定操作者、Workspace 和过滤条件，默认 25、最大 100。归档保留资源键及不可变版本；恢复要求相同的编辑/环境权限。
