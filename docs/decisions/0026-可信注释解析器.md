# 0026 可信注释解析器

- 状态：implemented（受限 Shell / CSS / Java / HTML 注释适配，本切片独立规格与质量审查通过；全仓门禁仍未通过）。
- 日期：2026-11-17。

## 1. 背景

全仓源码注释覆盖率必须大于 40%，遇到未支持的语法不能给出权威比例。
依赖冻结时有 48 个 unsupported；本切片只减少已接入路径，仍有未支持语言，比例保持 `None`，硬门禁仍然失败。
可信注释范围必须来自成熟语法解析器，不能用正则把字符串、heredoc 正文或 CSS URL 当成注释。
本决策先冻结开发工具闭包，再接入下述受限注释适配；不改变产品运行行为或整体验收状态。

## 2. 决策

在 `apps/srv/pyproject.toml` 的 dev group 中精确固定以下五个独立包，使用 uv 正常生成锁文件：

| 包               | 版本   | 原文许可 | 用途                                    |
| ---------------- | ------ | -------- | --------------------------------------- |
| tree-sitter      | 0.26.1 | MIT      | 固定语法树核心与字节位置                |
| tree-sitter-bash | 0.25.1 | MIT      | Bash / 明确 POSIX-sh 输入的注释语法边界 |
| tree-sitter-css  | 0.25.0 | MIT      | CSS 注释语法边界                        |
| tree-sitter-java | 0.23.5 | MIT      | 受限 Java 原始源码注释边界              |
| tree-sitter-html | 0.23.2 | MIT      | 仅外部脚本限定域的 HTML 注释边界        |

不启用这些包的可选 extras。首次锁增量为三个包，Java 与 HTML 切片各另增一个包，没有新增传递运行依赖。
已有包的版本、来源与解析标记均未移动，产品 dependency list 和生产闭包保持不变。
开发环境沿用 `uv sync --project apps/srv --frozen --all-groups`，不依赖全局安装的解析器。
使用单独官方 grammar wheel；不采用会在运行时联网下载 grammar 的 language pack 或插件发现。

适配范围为 `.sh`、精确路径 `deploy/desktop/macos/scripts/preinstall`、`.css` 与下述限定域的 `.java`、`.html`。
Shell 首行必须精确为 `#!/usr/bin/env bash` 或 `#!/bin/sh`（接受 CRLF）；未知、缺失或其他解释器保持具名未支持。
语法解析仅用于注释位置，不执行 shell，也不验证 POSIX 运行语义；shebang 不计说明注释，但保留为非空代码行。
适配器按需加载当前语法包，并核验核心与原有三个语法包的冻结版本。仅需处理 HTML 时核验 HTML 包版本。
核心 ABI 范围为 13～15，精确语言 ABI 为 Shell 15、CSS 15、Java 14、HTML 14。
解析器缺失、版本漂移、ABI 不兼容、`has_error`、`ERROR` 或任意 missing 节点均使整次解析失败关闭。
原始 UTF8 字节范围必须不越界、不重叠、与原文相同且位于码点边界，然后才转换物理行与 Python 码点坐标。
库存枚举与显示列宽不导入可选解析包，坏语法不能被当成零注释。
HTML 只接纳下述外部脚本限定域。其他嵌入语言和 native 源码继续阻断。

## 3. HTML 的外部脚本限定域

以严格 UTF8 原字节解析完整 HTML，拒绝错误或缺失节点以及根节点错误状态，再验证全部语法节点和上下文。
允许普通 HTML 元素、标准 `<!doctype html>`（大小写不敏感）、空元素和语法树接受的可省略结束标签。
元素名单和可接受的节点类型在适配器中明确定义。标签及属性间隔使用 HTML 的 ASCII 空白定义，属性名采用普通 ASCII 拼写。
拒绝未知元素或节点、命名空间和外来内容、`style`（元素或属性）、`textarea`、`xmp`、`iframe`、`noembed`、
`noframes`、`plaintext`、`template`、`noscript`、事件属性、`srcdoc`、`is` 和 `http-equiv`。
`title` 必须有明确的开闭标签，正文只允许树识别出的文本及实体。
原字节中的常见模板标记（含 `{{`、`{%`、`<%`、`<?`、`${`）使整文失去资格，包含其字面量的合法正文亦可能被拒。

`script` 必须有明确的开闭标签，正文仅允许空内容或 ASCII 空白。属性名按 ASCII 大小写折叠查重，
唯一必需的 `src` 以 `/` 或 `./` 开头，后面是由 ASCII 字母、数字、`.`、`_`、`~`、`-` 组成的非空路径段。
协议相对地址、路径外字符、查询、片段、实体、转义及 `href` 代替 `src` 均不在接纳域。
`type` 可省略或为空，另接受 `module`、`text/javascript`、`application/javascript` 的原始小写拼写。
附加属性仅允许 `async`、`defer`、`nomodule`、`integrity`、`crossorigin`、`referrerpolicy`。
内联代码、数据脚本或未知类型使整文失败。适配器不读取引用目标或执行输入。

固定语法可能把 `title="<!--伪标记-->"` 中的属性值标成 comment 节点，且不报告错误。
只有文档或已接纳普通元素的直接子 comment 有资格，`title` 的特殊树形限制仍适用。
注释必须具备原始 `<!--` 和 `-->` 边界，拒绝会使浏览器提前结束注释的异常边界和嵌套标记。
资格不足的合法 HTML 也会具名失败，版本、依赖或 ABI 错误同样停止审计与块检查，不输出部分范围或分母。

正文计数只移除 HTML 开闭界符，保留正文的 `/*`、`*/`、`#`、`*` 和全部原始物理分行。
只有非空正文计入注释行，相邻 HTML 注释各自检查首行；同一物理行的真实代码和正文各计一次。
块排版消费同一资格及范围，`--fix` 保留 HTML 字节。四个实际跟踪页面通过整文树和上下文验证，返回零真实注释并保留代码行。
外部引用的 JavaScript / TypeScript 各按其自身库存路径计量。

## 4. Java 的原始字节限定域

JLS §3.3 在注释形成前翻译 Unicode escape，原始 `\u000a` 可改变注释边界。
因此任何 `.java` 原始 UTF8 字节出现 ASCII 反斜杠紧跟小写 `u`，均在 parser 构造和 parse 之前整文件拒绝。
不判断资格、反斜杠奇偶、重复 `u` 或十六进制有效性，不替换字节、不实现 Unicode normalizer。
这会有意拒绝部分合法 escaped literal，包括普通字符串、文本块和注释中的非 eligible 拼写；不承诺完整 JLS 验证。
按 [JLS §3.4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-3.html#jls-3.4) 和
[§3.7](https://docs.oracle.com/javase/specs/jls/se21/html/jls-3.html#jls-3.7)，裸 CR 是 Java 行终止符，
但固定语法可能把它后面的代码并入行注释。Java 适配也在构造 parser 前整文件拒绝任何未紧跟 LF 的原始 CR 字节，
即使它出现在合法注释、类声明或文本块中。LF 和完整 CRLF 继续接受，源码字节不会为解析而改写。
拒绝返回有界英文路径、类别和行号，无源码正文、部分范围、部分 JSON 或静默分母排除。

其余输入由固定 Java grammar 的 `line_comment` / `block_comment` 节点交付原始范围，
仍检查 ERROR、missing、root.has_error 以及共享 UTF8 字节与码点坐标。
审计与块排版都使用此成熟范围，Java 不再走旧 native scanner。
Java 行注释只剥离正式 `//`，保留正文中的 `/*`、`*/`、`#`、`*` 及可能影响正文行号的前导物理分行；
块注释去正式边界及装饰前缀。
只有有效正文计注释行，空分隔符不抬分；代码与非空注释同行双计，遮罩保留全部 splitlines 物理分行符。
当前四个 Java 夹具共 30 个真实注释且没有两类受拒字节，未改写或执行这些输入。
该实际加载与语法证据只支持上述限定域，不宣称一般 Java 程序合法性或完整语言支持。

## 5. CSS 的保守上下文限定

固定 grammar 对 `a{background:url(foo/*literal*/bar)} /* real */` 不报告语法错，
却把 URL 数据中的 `/*literal*/` 错标为 comment。
[CSS Syntax 3 的 consume a url token](https://www.w3.org/TR/css-syntax-3/#consume-url-token)
将该未引号 URL 中的字符作为 token 数据；不能仅凭 comment 节点推导真实说明。
此前预检的未引号 URL 只覆盖双斜线地址，不能当成本反例已经被覆盖。

因此只接受直接父节点为 `stylesheet` 或 `block` 且没有 `call_expression` / `arguments` 祖先的 CSS comment。
其他上下文一律返回有界英文 `Unsupported CSS comment context` 错误，整次审计或修复停止，
不静默忽略节点或路径、不输出部分报告、不回退旧 scanner，也不自行归一化函数名或编写 URL lexer。
这是有意保守的子集：函数参数、声明等处的一些合法真实注释也会被拒绝，不宣称任意 CSS 全面支持。
大小写、转义 URL 名称及 quoted URL 函数旁注均有拒绝回归；普通 quoted URL 字符串与安全顶层 / 块注释仍可使用。
注释审计与 `.css` 块排版消费同一成熟范围及此限定；SCSS / LESS 与原生块排版保留既有行为，不获得比例支持。

新增 Shell / CSS / Java 仅累计真实范围内非空正文行，空分隔符不抬分，代码与非空注释同一物理行仍双计。
Shell 正文只移除实际井号与前导空白，普通斜杠、星号及后续井号保留；CSS / TypeScript 的字面井号不被移除。
旧 TypeScript 的关闭分隔符旁有代码时也计注释行，以及既有通用 C 分隔符正文剥离顺序，均按旧契约保留，
作为后续计数语义债单独审查。
新增 Shell / CSS / Java 的遮罩保留 CR/LF 及 Python splitlines 的 VT、FF、FS、GS、RS、NEL、LS、PS 物理分行符，
防止注释空行错移后吞掉后续代码；这只保留原文边界，不归一化内容或新增 lexer。
既有 TypeScript 遮罩仅保留 CR/LF 的边界行为在本切片保持不变，其 Unicode 分行语义另作既有债审查。
全局必须严格大于 40%，不存在逐文件配额；支持子集的 `observedRatio` 不能替代 `ratio=None` 的不完整结论。
YAML 工作流 / GYP 等嵌入代码分类仍待研究，native 等未支持语言继续阻断。

## 7. 验证与后果

普通冻结服务环境在 Python 3.12.14 / Linux x86_64 中实际加载四种语法。
核心接受 grammar ABI 13～15，Bash 与 CSS 实测均为 ABI 15，Java 与 HTML 为 ABI 14。
合成测试各从可信范围提取真实注释并排除伪标记。
该加载证据不代替 Mac / Windows 加载验证；适配器另有真实语法及消费者回归，仍不代表全仓覆盖率已通过。
规范化导出使用 `uv export --project apps/srv --frozen --no-dev --no-header`，
无哈希变体再加 `--no-hashes`；两者保留单独的 editable 项目行。
这两组完整原始输出前后逐字节相同，各有 56 条第三方 requirement；
含哈希导出的 SHA256 为 `aa60f90b349cd5bd1eaffc2447266d58d1468fc7ed6d45d4dbbc0a57b2f06a44`，
不含哈希导出为 `be8ce958ee8f7db6ea70b35e92652842eb2303e03daa52d5e0f96c01146837a6`。

正式 wheelhouse 使用 `uv export --project apps/srv --frozen --no-dev --no-emit-project --format requirements-txt`，

再与当前仓库实际最终输出比较，三者逐字节相同；这是基线重放证据，不是安装前执行该正式命令的声明。

## 8. 替代方案

不采用自制注释正则扫描器、Pygments token 猜测或自动下载全集 grammar 的 pack。
标准库 `HTMLParser` 提供事件及行列位置，无法直接提供本审计所需的完整错误树与原始字节范围。
`html5lib` 偏向浏览器式容错树构建，`lxml` 偏向 DOM 及容错恢复，树修正或重排均不能直接证明原字节注释坐标。
选择现有 tree-sitter 家族的独立 HTML grammar，验证语法树和原始 byte 范围后再归入受限计量。
native 及其他混合语法保留具名阻塞。
