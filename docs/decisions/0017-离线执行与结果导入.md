# 0017 离线执行与结果导入

<a id="0017-durable-disconnected-execution-and-separate-result-import-authority"></a>

- 状态：任务协调者于 2026-11-12 批准。

## 1. 决策记录

离线执行使用独立固定 Node24.22.1 运行时内置 `node:sqlite` 适配器（SQLite3.53.4，Node modules ABI137/NAPI10），不改变包/原生插件图。Node 为 MIT，SQLite 为公有领域；Windows 发行使用独立运行时，不依赖 Electron ABI。Windows 打包和原生保险库验收仍属 T20。已观测的适配器调用没有输出实验性警告。

私有 SQLite 数据库采用 `veriq_` 表、WAL 及 FULL 同步提交，跨进程拥有单一本地 Context。既有可信 Worker、编译入口、凭据代理、SDK 和原生进程监督器仍为执行权威。原生停止证据未知就保留隔离，时间流逝或关闭浏览器均不能释放所有权。每次调用都重新检查并捕获包签名、精确成员集合及字节。

导入结果使用独立离线记录，不使用在线 Attempt 租约/fencing/容量。导入 Run 的来源为 OFFLINE_IMPORT，gate 为 false。声明的设备/信任/环境事实与服务端验证的包/当前授权事实分开保留。Web 导入要求当前 Cookie/CSRF Workspace EXECUTE 及嵌套下载/草稿权限；设备导入使用当前认证登记及所有者/共享授权，不采用用户自报 ID。领域和请求头去重不可变，重放重新授权。有界原始证据传输复用私有发布世代/fence，原始证据仍需特权。

迁移 0013 增加离线导入、请求头键、Attempt 和上传表，并使发布所有权严格二选一：既有在线上传外键，或 Workspace 范围的离线上传外键。既有在线行保留原所有者。恢复和过期在退休世代前检查在线与离线别名，空物理屏障持续保留。存在离线导入/上传历史时降级拒绝，而非静默删除报告或发布权限。生产回滚因此必须保留此 Schema，或采用另行明确复审的数据保全流程。

既有有界包验证槽同时覆盖导入归档验证。ZIP/签名和原始 File/S3 I/O 在安装锁外执行，随后复核当前授权与世代。已提交结果冻结精确产物描述符，预暂存但未列明文件保持不可访问，晚完成不能附加它们。只有精确已完成描述符重放仍可接受，并须满足当前授权。

恢复原子领取精确 SQLite 所有权状态和 generation。已被恢复领取且未派生的所有者不得进入 SPAWNING；先赢得竞争的派生则要求原生停止证明。所有停止、完成、事件及检查点都由 generation 防护。SQLite Schema 版本 2 增加该字段，不丢弃既有本地历史。Attempt 交接与初始检查点一起提交；原始文件刷新后，ARTIFACT_CREATED 与其范围描述符一起提交。恢复保留证据，结果仍为 INCOMPLETE。

OfflineResultV1 可记录严格 executionChoices.browsers（一至三个唯一浏览器），省略表示 Chromium 回退。签名 SUITE 入口浏览器覆盖回退，签名角色/数据集覆盖保持权威。Runtime 与导入器按签名 CASE 选择或所选已发布/候选 SUITE 推导有界矩阵（最多 1000 变体）。导入将缺失变体投影为零 Attempt/事件的 INCOMPLETE CaseExecution；提交通过前缀不能抹除未执行工作。完整事实矩阵保留其真实结果。

已发布 SUITE 执行使用该 SUITE 保留的原源码、不可变编译描述符/文件和回执，直接 CASE 使用自身保留编译。仅 DSL 执行始终使用精确 draft/source.json。已发布 CASE 依赖保留独立原源码/回执审计来源和真实已发布 CASE ID，即使位于候选 SUITE 内；不能用逐 CASE 回执证明另一份 SUITE 编译。仅 DSL 导入事实保持保守，因为导出未携带候选独立验证的编译预期计划。

没有执行事实的旧结果，仅在签名选择与允许回退能为该 CASE 唯一确定一个变体时保守接受。旧结果归属有歧义返回 OFFLINE_VARIANT_FACTS_REQUIRED（422）。宿主保留本地历史和待上传状态，绝不为修复导入而重跑业务操作。这是明确的发行前兼容边界，避免捏造变体归属。
