# ADR 0006 — Deterministic compiler files and SDK handoff

Status: accepted T05 implementation boundary; production SDK, fixture execution and trusted Runtime completion remain T06/T07/T08–T10.

The compiler is a Node-only package. It consumes the canonical contracts and RFC8785 byte helpers without changing their browser-portable root. Node crypto verifies source identity and every document envelope. Ajv 8.18.0 and ajv-formats 3.0.1 validate fixture/assertion JSON Schemas without remote loading. TypeScript 5.9.3 is a compiler runtime dependency for deterministic AST emission. These exact versions were already approved and locked; no alternate DSL schema or crypto implementation is introduced.

`compileFiles(snapshot, distribution)` returns the strict `CompiledAssetBundle` descriptor and a path-to-Uint8Array map containing every actual file. `compileAssets` is its descriptor-only compatibility wrapper and requires the same explicit distribution. Missing distribution inputs fail with `ENGINE_DISTRIBUTION_REQUIRED`; the implementation supplies no pretend SDK, archive or integrity. The caller supplies the approved engine release's exact package.json, npm v3 package-lock.json, complete dependency inventory and local vendor archives. The compiler verifies engine/SDK versions, package/lock agreement, dependency closure and SHA-512 archive integrity. It performs no install or archive execution. Trusted release provenance, safe archive extraction and approved package contents remain the engine/Runtime/importer responsibility. Fixtures in compiler tests are explicitly isolated codegen/packing artifacts, never a production SDK fallback.

Executable files register a typed compiled case with `@veriq/runner-sdk`. A single generated `source/context.ts` shares frozen source context across all case entrypoints, avoiding case-count multiplication of the full closure. `source/asset-snapshot.json` provides the manifested cold-download context for Workspace/source/engine verification. CASE/SUITE executable context omits transient validationTarget. Zero-entry library sidecars retain validationTarget because it is required by AssetSnapshotV1; generated library TS exports only immutable asset data. No Run, attempt, machine path, runtime data row or credential value is emitted. Source identity remains exactly ADR 0005's projection.

A SUITE validation target selects the deduplicated pinned CASE version IDs, as the existing server producer does, and emits executable case entrypoints. The other six non-CASE kinds emit a validation-only library and cannot be assembled for TEST. A target-free execution source may retain exactly one SUITE root whose deduplicated cases equal the entry selection. Multiple matching suite roots are rejected as ambiguous; other unreachable assets remain errors. This permits stripping publication metadata without losing the frozen suite closure.

Flows preserve nested call boundaries: their observers span all children; wrapper assertions and extraction remain on the wrapper. Template parameters and flow parameters are evaluated once in the caller's scope and overlay scoped `data`; extracted and fixture values live in `vars`. Plans separate before assertions, response assertions before extraction, and assertions dependent on new extraction. The SDK must execute these phases, preserve literal data, validate extracted presence/types and dispose observers on every exit. Generated wire IDs are fixed-length SHA-256 keys derived from the deterministic expansion path; readable paths remain separate metadata. Original DSL remains in the source context.

Flow nesting is limited to five levels, and expanded steps (including call boundaries) to 500 per case/standalone flow. Assertion templates have the same five-level bound and a maximum of 5,000 visited expanded assertion nodes per case/standalone library, including template-call nodes. The additional breadth bound prevents a compact repeated-template DAG from causing exponential allocations. Exceeding a budget returns a semantic issue rather than throwing from array expansion. Unknown input types fail closed where an action requires a concrete type. Missing optional values are distinguished from null; binding and JSON Pointer resolution use own properties only and never eval or recursively interpolate resolved data.

For reproducible coverage evidence, `@vitest/coverage-v8` is pinned to 4.1.12, matching Vitest. Its ten newly locked packages have MIT or BSD-3-Clause metadata licenses, recorded in the npm inventory; upstream texts must accompany applicable distributions. Audit on 2026-11-11 reports no new advisory and retains only the reviewed moderate builder-only minimatch GHSA-g3hv-75wg-m249 described in ADR 0003. Vite remains the existing pinned 6.4.5 test/build dependency. No Python, browser SDK or production service dependency is added by this compiler task.
