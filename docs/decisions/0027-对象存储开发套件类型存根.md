# 0027 对象存储开发套件类型存根

- 状态：已实施，等待独立复审。
- 日期：2026-11-17。

## 1. 背景

S3 就绪检查需要严格验证客户端工厂、操作参数、响应流与传输哨兵的类型。
已安装的运行时 boto3 和 botocore 缺少供 mypy 使用的类型声明，导致惰性导入告警。
依赖固定在 Python 3.12，运行时 SDK 的版本与生产依赖闭包按现有发行基线保留。

## 2. 决策

使用完整重载系列，在 `apps/srv/pyproject.toml` 的 dev 组固定以下精确版本。

| 开发输入           | 版本       | 原文许可 | 用途                                                       |
| ------------------ | ---------- | -------- | ---------------------------------------------------------- |
| `boto3-stubs[s3]`  | `1.44.0`   | MIT      | 提供 `boto3.client("s3")` 和 `Session.client("s3")` 的重载 |
| `mypy-boto3-s3`    | `1.44.0`   | MIT      | 提供 `S3Client` 和 S3 请求与响应类型                       |
| `botocore-stubs`   | `1.43.126` | MIT      | 补齐 Config、异常、响应流和本地测试接缝的类型              |
| `types-s3transfer` | `0.19.3`   | MIT      | 补齐完整系列所需的传输类型声明                             |

完整系列可直接利用现有客户端工厂重载。显式固定 S3、核心和传输类型，避免根包的传递范围选择不同发布版。
唯一选中的 extra 为 `s3`，可选的 `all`、`full` 和安装运行 SDK 的 extras 保持关闭。
生产注解若需引用 `mypy_boto3_s3`，在 `TYPE_CHECKING` 内导入，使用字符串注解或延迟求值。
服务模块继续惰性加载运行 SDK。制品服务移除三处过期的导入抑制，Python AST 保持一致。
读对象就绪分支在现有客户端清理范围内显式拒绝绕过配置校验的 `None` 键，返回存储未就绪并关闭客户端。
经校验的读对象与仅查桶路径保留既有结果。

## 3. 备选方案

| 方案                          | 取舍                                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| 完整系列，仅选 `s3`           | 保留字面量服务名重载，直接推导 `S3Client`，可用于现有工厂和严格测试。接受核心类型落后一版的限定兼容面。  |
| `boto3-stubs-lite[s3]`        | 根 wheel 较小，仍依赖核心类型。省去客户端与资源工厂重载后，使用方需逐个标明返回类型。                    |
| 等待与运行 SDK 同版的核心类型 | 可消除核心版本差异。2026-11-17 查询 `botocore-stubs==1.44.0` 得到 HTTP 404，等待将推迟当前严格 S3 测试。 |

## 4. 兼容范围

精确比对了安装的 boto3/botocore `1.44.0`、S3 模型和声明中实际使用的 17 个请求与响应字段。
已核对 `Config` 的超时、重试和路径寻址选项、异常类型与状态码、客户端关闭，以及 HeadBucket、GetObject、
ListObjectsV2、PutObject、DeleteObject 所需参数和响应访问。传输类型包是开发依赖。
补充核对覆盖 `Stubber` 的响应与错误入队、激活、停用、剩余队列检查，`StreamingBody(BytesIO, int)` 的读和关闭，
`ReadTimeoutError` 和 `NoCredentialsError` 的测试构造，以及 `URLLib3Session.send` 的传输入口。

后续 S3 测试可用 `client.meta.events.register_first` 监听 `provide-client-params.s3`，按唯一 ID 注销。
运行时先发布此事件，再进入 Stubber 的 `before-parameter-build` 校验；应核对账本中非预期调用的次数，
以及 `URLLib3Session.send` 传输哨兵的零调用。旧核心类型未声明私有 `_make_api_call`，公共事件提供严格类型接缝。

核心声明的兼容承诺限于上述接口。旧 `Config` 声明缺少 `auth_scheme_preference`、
`ignore_configured_endpoint_urls`、`s3_disable_express_session_auth` 和 `user_agent_appid`。
`StreamingBody` 构造面的声明核对限于测试传入的整数长度，运行时内部还可传入字符串头值或 `None`。
SDK 静态形式核对、分发校验与本地替身探针只覆盖这些边界。真实端点、凭据、网络、部署及发行仍待各自验收。

## 5. 许可、安全与生产闭包

四份官方 wheel 的摘要与 PyPI 及 uv 锁记录一致，内部 RECORD 和 160 个安装载荷逐项校验。
实际 LICENSE 均为与 VeriQ 的 AGPL-3.0-only 项目许可兼容的 MIT 原文。分发这些开发工具时须保留原始版权、许可及免责条款。
2026-11-17 对四个精确 PyPI 版本的 OSV 请求返回 HTTP 200，四项均无匹配；结论限于查询时点和范围。
原始许可、官方来源、摘要和 OSV 请求响应见 [SDK 类型审计](../dependencies/v09-sdk-types-audit.json)。

正式的冻结 `--no-dev` wheelhouse requirements 导出前后逐字节相同，仍为 56 项第三方需求。
既有 112 个非项目锁记录逐字节相同；项目锁记录只增加 dev 依赖和对应元数据。
运行时 boto3 `1.44.0`、botocore `1.44.0` 与 s3transfer `0.19.3` 沿用现有锁定输入。
生产服务包和 Runtime 使用既有运行时边界，新增类型分发包仅进入开发安装。
