## 接手规则

1. 读取 `AGENTS.md`、需求规格、主里程碑和代码交付计划，记录实际分支、提交、锁文件和目标平台。
2. 使用独立工作目录与测试数据库；禁止使用真实业务数据或替换已有证据。
3. 先确认前置条件，再执行每项任务；缺少环境、凭据或人工授权时标为阻塞，不得自动跳过并计入通过。
4. 按批次执行定向检查，再做完整集成与整分支复审。任何修复应形成新提交，并明确哪些旧结果已失效。
5. 保留失败、日志、实际执行命令、退出状态、提交与产物摘要；不要求为每个命令重新封存整个仓库。

## V08：正式发行

执行默认 `./build.sh`，不得借用 `--skip-tests` 取得正常成功结论。确认前端先编译并进入 `apps/srv/src/veriq_server/static/dist`，wheel 包含完整资源与库存；仓库外、无 Node 的 Python 环境能启动控制服务。再验证外部数据目录、深链接、静态/API 404、只读安装、离线 wheelhouse、Compose/OCI、升级失败恢复和产物清单。无正式签名材料时只标记候选，不发布正式发行。

## V09：质量与规范整改

先执行新代码的类型、格式和定向 lint，再执行完整固定依赖测试及覆盖率。Python 与 TS 核心行覆盖率目标各不低于 75%。注释必须解释具体职责、不变量和失败边界，遵守 4 空格、中文源码注释、英文日志、公开 API 和注释首行要求。对现有已知规范缺口先进行实质整改再审计；这是待完成质量工作，不是已获豁免。核验依赖许可证、锁、SBOM、NOTICE 与 AGPL-3.0。
