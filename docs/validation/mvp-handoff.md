## 接手规则

1. 读取 `AGENTS.md`、需求规格、主里程碑和代码交付计划，记录实际分支、提交、锁文件和目标平台。
2. 使用独立工作目录与测试数据库；禁止使用真实业务数据或替换已有证据。
3. 先确认前置条件，再执行每项任务；缺少环境、凭据或人工授权时标为阻塞，不得自动跳过并计入通过。
4. 按批次执行定向检查，再做完整集成与整分支复审。任何修复应形成新提交，并明确哪些旧结果已失效。
5. 保留失败、日志、实际执行命令、退出状态、提交与产物摘要；不要求为每个命令重新封存整个仓库。

## 建议执行顺序与隔离

1. 先执行 V00 和 V09 中不需要外部环境的契约/静态/规范检查；修复后记录新提交，确定哪些旧结果失效。
2. V01、V02、V04、V06、V11 可按前置条件拆开执行。数据库测试使用隔离实例/容器和其要求的 `veriq_test` 数据库，不能并行重置同一数据库；原生/profile 测试使用独立账户与目录。
3. V05/V03 在实际目标材料、独立 Expected 和必要人工材料就绪后执行；V07 只在明确授权预算及配置后执行。最后完成 V08 正常发行和 V10 整体验收/整分支复审。
