## 接口与生命周期

`withDependencyInputViews<T>(work, options, consume)` 从 `runtime-payload-dependencies.ts` 导出。`work` 必须为已经初始化的独立 `ArchiveTransaction`，`profile: "work"`，`views` 为空。回调为：

```ts
consume(
    inputRoot: string,
    trees: Readonly<{ dependencies: BoundTree }>,
    generated: WorkspaceGenerationEvidence,
): Promise<T>
```

`options`：

| 字段 | 合同 |
| --- | --- |
| `source` | 已固定的 `SourceBindingV1`，含完整原清单、contracts/SDK 源码、contracts 的 Schema、LICENSE、锁、pnpm 工作区配置、实际生产器与观察器源码 |
| `dependencies` | `Omit<Build,"commandEvidence">`；生产器为 `apps/runtime/scripts/runtime-payload-dependencies.ts`，config 为 `pnpm-workspace.yaml`，tools 为 node/pnpm，sourceBindingSha256 为来源文档的 JCS SHA256 |
| `buildRoot` | 调用方独占的绝对、规范、真实、0700 空目录，与源码及事务父根互不覆盖；调用方负责最终清理 |
| `consumers` | `{inputRoot,entries:BoundTree,execution:BoundTree}`，来自已完成且仍在所有权窗口中的真实入口/执行树 |
| `hostBuild` | `{executable,pnpmCli,pnpmStore,timeoutMs,run}`；`run` 使用既有 `HostBuildInvocation -> Promise<HostBuildObservation>`，单动作最多 16 分钟 |
| `targetNode` | `{executable,version,artifactSha256}`；必须是真实目标 Darwin 架构的独立稳定 Node24，`artifactSha256` 为**可执行文件**原字节 SHA，不是 Node 归档摘要 |

安装命令固定为 `node <pnpmCli> --filter @veriq/runtime... install --frozen-lockfile --offline --ignore-scripts --prod --node-linker=hoisted --package-import-method=copy --store-dir <pnpmStore>`，pnpm 实际版本必须为 11.25.0。不 fetch、不重写源锁、不修改源 manifests，不增加全局 Worker 加载器。引擎 compiler 的 TS 路径及其已有显式 tsx 调用保持由既有引擎流程提供。

输出 `inputRoot = work.scratch/views`，BoundTree.root 为 `dependencies`；库存、收据和命令材料位于 `input-evidence/dependencies-{inventory,receipt,command}.json`，另有原布局、真实命令 stdout/stderr、解析、optional、原生 bin 和 workspace-generation 材料。原源码副本保留其原路径；生成清单只在依赖树中。回调结束后再次核来源、消费者、工具、文件摘要、目录身份、视图及事务。C05 必须在生产器成功返回后才提交第三归档接收中的合并结果；不能把回调已取得的路径当成跨生命周期的授权。

`materializeRuntimeWorkspacePackages({sourceRoot,outputRoot,source,files})` 另行导出。生成证据明确列出 originalManifest、generatedManifest、originalSourceRefs、所有输出以及实际 TypeScript 模块/清单/读取事实；现有公共收据不独立证明源码到生成文件的转换，所以不能将这些材料扩大解释为发行者认证或来源晋升。

## bin 与解析政策

- 所有包声明的 bin 都保留 owner、原目标路径、真实目标字节和启动器分类。安装 Shell 启动包装脚本不当成包目标正文。实际公共 `.bin/name` 赢家由本次持有的链接目标或有限 pnpm shim 的 `exec` 目标确定；不能按包遍历顺序选择。
- 公共赢家的真实安装 alias 保存为 `sourceAlias`。链接以最终布局的相对目标登记；原链接原文仍在布局证据中。被同名覆盖的其它声明使用 `<install-level>/.bin/.veriq/<sha256(full owner.id)>/<name>`，sourceAlias 为 null。没有真实赢家、多个不同赢家或未知 shim 形式均拒绝。
- 无扩展名的 Node 目标仅接受精确 `#!/usr/bin/env node` 或 `#!/usr/bin/node`，无参数、CR 或其它解释器。目标文件不改名、不搬到 alias、不改 manifest；原生目标实际运行 lipo/otool 并要求目标单一架构与不高于 15.0 的系统要求。
- 每个根的真实 consumer/specifier 必须精确保留。依赖边的真实 Node 解析证明可以为 alias 本身，或相同已解析的包别名的实际子路径；优先真实本次持有的命令，再尝试可由 Node 导出的 package.json。平台 esbuild 包没有包根入口时，不能伪造根解析成功。
- 目标 Node 在独立物理树上用真实 `import.meta.resolve` 与 `createRequire.resolve` 记录结果，不加载包正文。两个条件指向不同实例时失败，不自行解释 exports。结果写入限额 JSON 文件，stdout 只返回摘要，避免超过既有有界进程 64 KiB stdout 限制。

## 已知支持边界与尚需确认的真实布局

当前是**固定仓库锁**生产器，不是通用 YAML 或 exports 解释器。snapshot 键与平台字段只接受该锁的现有两级缩进/标量/flow-list 形式；peer 上下文先依靠真实已安装 peer 版本消歧，仍不唯一时以 `DEPENDENCY_SNAPSHOT_AMBIGUOUS` 拒绝。目标排除需要精确名称版本；可选 npm 包别名/range 若不能直接从固定锁键取得精确平台记录，会失败，需要后续实际夹具明确支持，而不会生成假排除证据。

支持 root node_modules、Runtime 导入器和 contracts/SDK 局部 node_modules 的物理路径映射，并保留嵌套实例。如果不同安装域映射为同一最终路径而代表不同物理实例，以 `DEPENDENCY_INSTALL_SCOPE_COLLISION` 拒绝；未实现任意单仓多项目安装域的布局重排。若真实固定锁触发该拒绝，这是**剩余功能工作**，不能仅记作验证失败后宣称已完整交付。当前未运行安装，因此实际布局是否触发尚未知。

未知 pnpm shim、无法唯一判定的公共命令赢家、其它工作区目录链接、自有包内链接、跨条件实例分裂、通用原生多架构二进制检查均失败关闭。原生 lipo/otool 的本次输出尚未取得；当前源码不能据此声称任何二进制已验收。专用故障/peer/optional/bin 测试源码尚未编写，完整源码差异复审与真实执行均留待独立验证阶段。
