## 已确认的问题

原基线的 Linux 暂存退休在确认进程停止后，检查目录、文件身份、单硬链接与挂载，再对已经打开的文件句柄截断。
最后检查和写入之间仍存在竞争窗口：其他具备权限的进程把原文件移出任务树，原句柄仍指向那个文件，
随后的截断会清空已经移走的原件。写入后再检查可以报告不确定，却不能恢复原内容。

[原基线实现](https://github.com/baofengbaofeng/VeriQ/blob/114f838ba408775050f774870e1a1d86438779c3/apps/runtime/src/execution/storage.ts#L347)中的关键顺序是：

```ts
await verifyMember();
await file.truncate(0);
await file.sync();
await verifyMember();
```

[基线故障测试](https://github.com/baofengbaofeng/VeriQ/blob/114f838ba408775050f774870e1a1d86438779c3/apps/runtime/tests/journal-recovery.test.ts#L597)在 `truncate` 边界执行移动，
断言新占用原路径的文件保留，而移走的原文件内容为空。这与[公共契约](../公共契约.md#联网任务的证据与恢复)
要求“成员移动、替换……均保留”冲突。本轮已静态核对实现及测试断言，并从 `apps/runtime` 运行这个精确文件故障用例：
退出 0、1 项通过，实际检查移走的原件内容为空。这确认了旧测试接受危险行为，不能当作修复通过。
第一次从仓库根运行因根包不拥有 `tsx` 而在加载前失败，原记录保留；改用正确包目录后才进入上述真实用例。

0700 私有目录可以限制其他账户；进程排空证明只覆盖本次受控后代；一次性许可可以协调遵循协议的清理调用。
它们均不能证明不存在另一个同 UID 写入者或宿主操作。文件描述符固定 inode，不固定它在任务树中的位置。
再次增加路径检查仍会留下检查与写入之间的窗口。

## 已比较的处理方向

| 对比项         | 保留现场，暂停缺少排他证明的自动清理（建议用于首版）                          | 先增加存储隔离，再提供自动清理                                            |
| -------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 核心行为       | 不截断或删除无法证明排他所有权的可变树；保留现场并报告待处理                  | 从任务创建起隔离存储和写入主体，实际证明独占回收权后才允许清理            |
| 平台影响       | Linux 也保留这类暂存；Mac/Windows 现有保守保留语义不变                        | 需要新的 Linux 隔离设计、权限/内核/文件系统支持及发行运维验证             |
| 磁盘影响       | 已结束任务可能累积依赖与中间文件，需要容量监控及人工回收安排                  | 目标是自动回收；具体实现和运维成本目前未验证                              |
| 停止与业务结果 | 不改变真实停止证明；停止未知仍隔离；清理不确定与业务结果分开记录              | 同样不能降低停止或业务结果保证                                            |
| 主要代价       | 首版不再承诺对这些 Linux 可变暂存自动回收，须明确低磁盘暂停领取及人工处置方式 | 增加平台工程和验收工作；不能仅凭 mount namespace 或再次核验路径就声称安全 |

建议的保留方案还需落实以下产品行为，不是仅关闭代码后就视为完成：

- 已确认停止时记录 `OWNERSHIP_UNCONFIRMED`；未确认停止仍为 `STOP_UNCONFIRMED`，不放行未知进程容量。
- 管理员能够看到待处理的本机清理状态及恢复指引；不记录私有文件名或秘密正文。
- 对历史累计磁盘占用建立领取前保护；磁盘不足时暂停新任务并给出诊断，不自动删除来源不明的目录。
- 人工回收须先确认主机访问和目录归属，保留规定的报告证据；不把人工操作伪装成自动安全擦除。
- 既有历史回执保持原始含义，正常结束和启动恢复使用相同边界。

若选择隔离存储方案，应先明确允许访问的主体、其他挂载视图、保留句柄、升级及崩溃恢复行为。
独立 mount namespace 只改变可见性，本身不阻断其他视图对同一底层对象写入。
专用文件系统、分离 UID 或强制访问控制均只是候选，当前没有证据证明它们已适配全部目标部署。
