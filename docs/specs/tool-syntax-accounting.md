# Tool syntax accounting

## 目标与批准范围

用户于 2026-11-18 确认：经语法上下文及工具行为验证的固定工具标记按功能代码计量。
它们不计入有效注释分子 C，仍保留在非空代码分母 K；不得直接从统计范围中删除。
普通说明仍须中文，独立单行及块首行有效正文 40～120 个 Unicode 字符，整物理行最多 120 显示列。
全仓 C/(C+K) 必须严格大于 40%，不得用工具语法豁免扩大有效注释数量或隐去代码。

## 首次支持的语法

首次支持范围为 JavaScript / TypeScript 动态 `import()` 首个参数之前的独立块标记 `/* @vite-ignore */`。
必须由冻结的 TypeScript 5.9.3 AST 确认是动态导入调用，标记位于首个实参的前导 trivia 区间。
标记完整词元须匹配 Vite 6.4.5 的固定语法，空白字符按 JavaScript 的 `\s` 语义处理。
大小写变化、附加中文或其他正文、普通对象的 `import` 方法、类型导入、调用之外的同形说明均不合格。
字符串、模板、正则及 JSX 正文中的同形文字本来就是代码，不得被桥接器识别为注释。

桥接器只在合格的真实注释区间上增加 `codeDirective: "vite-ignore"` 字段。
既有位置、原始文本与码点坐标保持不变；普通区间保持原有 JSON 形状。
整批源码仍先通过现有语法检查，任何文件解析失败均不得输出部分可信区间或分类结果。
审计器仅接受该已知分类；未知值与未分类注释保持普通说明处理，不新增可配置前缀白名单。

## 计量与其他检查

合格工具词元不生成说明正文问题，也不纳入有效注释行；它的原始字符不参与注释遮罩。
同一物理行出现多个标记或代码时，代码行仍只计一次。
同一行若还有普通说明，说明独立按原规则计量和验收，不能随工具标记一起豁免。
换行仍采用既有 TypeScript CRLF、CR、LF、LS、PS 口径；中文及补充字符不得改变坐标。
显示列宽检查继续覆盖这些工具词元，工具标记不得成为超宽代码的例外。

Shell 文件开头的 shebang 维持既有功能代码处理；除下述 Python 精确范围外，不扩展其他工具指令。
排版器现有 pragma 保留逻辑不等于注释计量白名单，不得复用宽泛的前缀正则作信任依据。
后续支持其他固定语法，须分别给出成熟解析器上下文、实际工具行为和正反例证据。
分类表明该词元处于工具已知语法的合格位置，不保证每个参数都进入消费分支；
例如静态可解析的导入参数可能不会触发相关警告分析，不能将分类解读为每次转换都会改变输出。

## 可观察验收

使用实际 Vite 公开转换 API 对同形合成动态导入进行正反例转换，观察警告或输出差异，
并验证固定标记没有被改写；不能仅复制 Vite 的正则或检查源文件字符串冒充行为证据。
测试不启动监听端口、不下载依赖、不加载项目配置或真实环境凭据，服务和临时材料须完整关闭清理。
这只证明 Vite 对该语法的消费，不证明 Playwright 的 `page.evaluate` 回调实际经过 Vite 编译。

端到端调用实际桥接器和审计 CLI，独立断言 C、K、问题、门禁退出码以及失败批次没有部分 JSON。
保留原有解析器测试和阈值；新测试覆盖合格位置、近似拼写、不合格宿主、混合说明和换行坐标。

## Python 行尾类型检查指令

本节按既有 C=0、K 保留原则限定下一项接入，实施状态由 ADR 0030 和验证计划记录。
协调者根据现有 CPython 3.12.14 与 mypy 1.19.1 实测选择下述范围，不新增依赖或修改原工具词元。

仅接纳完整真实 COMMENT 词元 `# type: ignore[no-any-return]` 与 `# type: ignore[arg-type]`。
CPython 辅助类型注释 AST 的同一物理行须存在精确 `[no-any-return]` 或 `[arg-type]` 标签。
该行须已有原计量规则认可的真实代码，并在 COMMENT 之前存在起止均在本行、位于文档串范围之外的
NAME、NUMBER 或 STRING 词元。跨行字符串的收尾、只有括号或分号的收尾行、纯注释行不合格。
完整词元不接受大小写变化、空格改写、尾随空白、多码、未知码、裸 ignore 或附加正文。
其他形式继续按普通说明验收，不以宽泛前缀分类。

普通 `ast.parse` 继续决定文档串和已有 Python 语法有效性。
附加的 `ast.parse(..., type_comments=True)` 如因类型注释语法抛出 SyntaxError，只不给本文件工具资格；
默认 AST 可接受的源码仍按既有规则产生计数，不能被辅助分类缩窄。
默认解析本身失败则维持原失败路径，不能产生部分成功报告。

合格词元不构造普通说明块，C=0；同行原有 K 不删除、不重复增加。
同组相邻普通说明仍按原物理行规则检查，不能继承工具资格。
特别是 `contracts.py` 的第一处标记之后原有短中文说明，接入时须独立准确补充至既有正文要求，
不得改变通用分组规则、修改标记或额外排除路径来掩盖该问题。
字符串或文档串中的同形文字维持原处理，未知标记也不从范围中删除。显示列宽仍覆盖全部物理行。

真实 mypy 合成静态检查须分别观察：精确标记消除两类错误、移除后出现两类错误、
无待抑制错误时产生 unused-ignore、错拼产生语法诊断。夹具不执行代码，不继承项目插件或凭据。
资格只说明该词元在已验证的工具语法位置，不保证任意源码都没有类型错误或必然抑制某项诊断。

验收还须覆盖 CRLF/CR/LF、中文及补充字符、独立注释/闭括号行/跨行字符串收尾、实际实参行、
混合普通说明、文档串前后代码，以及辅助 AST 失败时的默认解析兼容性。
通过真实审计函数与微型仓库 CLI 断言 C、K、正文、JSON 形状和阈值退出码，保留全部既有工具测试。
