# VeriQ 对话测试 Agent

Web 管理台和 Electron 在线工作区共用一个控制服务端对话 Agent。它根据多轮需求制定测试计划，修改已经保存的执行计划，触发测试并展示进度及结果。现有 Runtime 和执行队列承担实际测试。桌面端通过类型化 IPC 调用服务端并复用 Web 视图。

## 会话和模型

- 会话属于当前登录用户及 Workspace，支持多个会话、分页历史、跨端继续和归档。成员身份和会话所有权在每次请求时检查。
- Workspace 管理员分别配置工作区默认 Provider 和对话 Agent 专用 Provider。未绑定专用 Provider 时继承工作区默认值。显式选择的 Provider 无法使用时返回原因。普通执行和历史查看仍可使用。
- 每轮冻结 Provider 及修订，在既有 AI 预算中预留用量。模型只收到有界、允许的会话内容和脱敏资源投影。使用既有网关的 JSON 输出，不增加依赖。私人对话不出现在工作区共享的 AI 生成历史中。

## 计划到结果

- 以用户描述和对话中的修订为输入，优先匹配已发布用例及套件。参考已有计划补齐工作区配置，展示具体选择、假设与覆盖缺口。验收依据缺失时标明待确认。
- 新建和已有计划调整都显示结构化预览。调整仅覆盖用户指定的更改，保留计划 ID 和无关配置。保存计划使用当前修订，冲突时请用户查看新版本。只对本次运行的更改复用一次性 Run 路径。
- 可复用执行计划需要已发布套件。仅有一组已发布单用例时支持一次性 Run。缺失资产可列入覆盖方案，后续沿用既有审核和发布流程。
- 使用当前员工身份和现有业务服务保存和触发。写入或派单所依据的计划版本、参数和所有权由控制服务检查。重复确认或重试只产生一次已确认的副作用。
- 会话持久化真实操作回执和 `runId`。用例进度与报告从现有 Run 契约读取。离开或重新进入对话不改变运行生命周期。需要时可以打开完整报告。
- Web 和 Electron 使用同一 Workspace HTTP 契约。内置 Agent 直接调用业务服务。外部 MCP 工具留待具体接入需求。
