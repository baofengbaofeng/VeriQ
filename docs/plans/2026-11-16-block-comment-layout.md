状态：源码和生成器已修正；全仓格式及显示列宽静态扫描完成；业务测试、构建与独立复审待后续执行。

## 用户确认的规则

- 注释长度统计有效正文的 Unicode 字符，不计缩进、注释分隔符、行前缀和首尾空白。
- 独立单行注释及块注释的首行有效正文为 40～120 字符；块注释续行不设 40 字符下限。
- 每个物理行仍最多 120 个显示列，计入缩进和注释符号；中文等宽字符占 2 列。
- 独立 C 风格说明块的开头和结尾必须各自独占一行，正文从下一行开始并使用 ` * ` 前缀。

```ts
/**
 * 使用真实临时文件验证导出副本在成功、取消及查看器失败后均被回收，同时保证原始证据字节不受影响。
 * 续行允许更短，不能为达到字符数而填充没有信息的句子。
 */
```

首行指上例的首行有效说明，不是只有 `/**` 的分隔符行。
普通独立 `/*` 及 `/*!` 块保留原有开头标记，采用相同排版。
Python 文档串等其他语言语法保持不变；字符串、模板和正则中的注释样本不按真实注释改写。

## 工具与核对

```bash
python3 scripts/comment_blocks.py
pnpm lint:comments
python3 scripts/line_width.py
```

工具默认检查，可用 `--fix` 修复指定普通源码；生成文件只检查，须修改生成器再生成。
JS/TS 复用已安装的 TypeScript 解析器；缺少解析器时明确失败，不返回虚假的零问题。
可通过 `--typescript` 显式指定已有编译器模块，避免为了扫描安装或复制另一套依赖。
真实行内工具指令保留语义，普通行内说明须人工移动到安全位置，不能因自动换行引入自动分号变化。

已完成的定向静态核对包括：

- 全仓块注释排版、120 显示列及 Git 空白扫描。
- 手写 TS/JS 及三份生成类型的去注释解析输出比对，字符串和代码结构保持一致。
- 原生源码的非注释字节或词法比对，代码与字符串不变。
- 桌面生成器的两份 JSON 输出保持原字节，未变更业务契约与依赖锁。

TypeScript 桥接新增已有编译器路径选择能力，默认仍使用仓库冻结安装的编译器。
排版工具不代替正文语言、内容质量与覆盖率审计；分隔符空行不能用于增加有效注释覆盖率。
