## 执行规则

- 复用现有 Python、React、Electron、TypeScript 和 Runtime 契约，不新增另一套执行引擎。
- 按互不冲突的目录并行实现；协调者按明确文件范围串行提交。
- 本轮不启动测试、构建、CI、付费模型调用、真实钥匙串操作或独立复审。所需测试源码可以补齐，执行留给接续任务。
- 不改动历史证据，不为本轮重复生成大规模快照和封存。既有失败、未知原因和未验证行为必须保留。
- 不移除构建、来源信任、权限、签名或数据隔离门禁，不产生伪造回执、假报告、空实现或硬编码成功。
- 每项代码必须附独立验证交接文件：入口、前置环境、步骤、预期、失败边界、所需人工材料、当前状态。
- 代码尚未实现的事项继续列为代码待办，不能只写入验证清单后宣称交付。

## 已知支持边界

这些边界必须进入后续验证和发布判断，不能被写成通过结论：Monaco 内部命令/查找菜单的缓存 NLS 不随语言实时切换，VeriQ 的标签与帮助已接入全局语言；Windows 旧 JSON/staging 保守隔离，不自动迁移；在线日志读取上限 4,096 条且未提供自动归档；未登记为可信缓存的任意目录/暂存文件不由保留期服务猜测删除，超限或引用不确定的结果保留。桌面手动更新要求引擎与数据格式符合现有兼容策略。全仓规范整改和实际目标环境验证仍见 V09/V11。
