## 1. 发行、配置与回滚

约束服务端/桌面/引擎发行物的完整性、可追溯与安全默认配置，降低错误发布与不可回滚风险。

### 1.1 构建完整性

- 生产服务端：Web check/build → 安全 stage 到 `static/dist` → wheel；缺 `index.html` 或清单则失败。
- 正式产物须含迁移、版本资料、校验和/SBOM/NOTICE 所需输入；禁止手工塞未知文件进发行目录。
- 默认完整测试；跳过测试必须带原因，且不得把结果标为已验证正式发行。
- 锁文件冻结安装；构建宿主与目标 ABI/OS 差异须被显式处理（wheelhouse、原生二进制按目标出）。

### 1.2 身份与晋升

- 引擎/候选包身份（版本、hash、批准状态）不可静默覆盖；晋升走独立流程。
- 桌面升级与回滚由用户手动启动已核验的安装程序，须验证签名并兼容数据库、本地日志和旧引擎。不得借更新强制取消业务执行。见 [Runtime 分发 ADR](../../docs/decisions/0021-运行时发行与原生边界.md)。
- 升级、回滚与卸载均把准备中的 `startupId`、正在执行的任务、在线 Worker、未知或隔离进程视为忙。替换或卸载文件前须取得同一次操作的真实停止证明。进程名扫描仅用于发现应拒绝的情况，不构成停止证明；禁止按名称强杀进程。
- 配置与构建产物不得混入密钥；`release.json` 等元数据须诚实标记测试是否跳过。

### 1.3 配置安全默认

- 默认拒绝不安全模式（例如关闭鉴权、允许任意 CORS、关闭签名校验）。
- 配置项须校验类型与取值范围；错误配置在启动/doctor 阶段失败，而不是带病运行。
- 区分开发与生产配置；生产不得依赖开发 HMR 代理或可写源码树。

### 1.4 回滚与备份

- 数据库迁移的回滚/前进策略在发布前写明；无法自动回滚时须有人工步骤与数据风险说明。
- 备份恢复演练对象包括库与制品存储配置；恢复后须再跑迁移版本一致性检查。
- 桌面卸载默认保留外置历史和配置，并文档化所保留的用户数据。升级失败不得静默清空凭证。

### 1.5 运行时运维接口

- 保留期清理、租约回收等走认证维护接口；有界批次 + 幂等 + `hasMore`。
- 无内部 Cron；外部调度配置示例与健康监控随部署资料提供。

### 1.6 检查清单

- [ ] 产物清单、hash、许可声明齐全且与锁文件一致
- [ ] 未把跳过测试的包标为正式验证
- [ ] 配置默认安全；启动校验失败关闭
- [ ] 回滚/备份风险已文档化
- [ ] 桌面升级或回滚有发布者签名和兼容性核验；替换或卸载文件前有本次操作的停止证明

## 2. 原生与跨平台要求

约束桌面/Runtime 在各 OS 上的进程、凭据、文件系统与停止证明，避免用单一平台假设冒充全平台正确。

### 2.1 目标矩阵

| 目标 | 要求 |
| --- | --- |
| macOS 15+ x64 / arm64 | 最高优先；宿主原生 Chrome；真实架构验收；Rosetta 不能代替另一架构结论 |
| Windows 11 x64 | 必须交付；Server 验证不能自动等同 Win11 安装验收 |
| Ubuntu 24.04 x64 | 必须交付 |
| 服务端 Linux x64 | 控制面无 Node/Chrome 运行时依赖 |

每平台分别构建与验收；禁止「在 A 平台绿了就声称 B 支持」。

业务 Playwright 浏览器在目标环境默认启用适用的沙箱，验收须提供实际启动、有界面与无界面运行及同一 Attempt 的停止证据。Electron 界面沙箱证据不能代替业务浏览器证据。宿主缺少必要授权时 doctor 须明确说明，不得放宽全局沙箱策略。见 [Runtime 分发 ADR](../../docs/decisions/0021-运行时发行与原生边界.md)。

### 2.2 进程命名与监督

- 真实 OS 进程名：`veriq` / `veriq_agent` / `veriq_runner`（及 Windows `.exe`）。
- Electron 内嵌 Node ≠ 锁定 Node 24 执行引擎；测试浏览器 ≠ 桌面 UI Chromium。
- Linux / Windows：全后代停止范围 `FULL_DESCENDANT_TREE`（subreaper / Job 等经核实机制）。
- macOS：`CONTROLLED_WORKER_BROWSER`；不确定则隔离；禁止写成 `DRAINED` 全树证明。
- 各平台仅在该 Attempt 的持久状态证明从未派生执行进程时，才可在停止回执中使用 `NO_PROCESS_SPAWNED`。`SPAWNING` 状态不明时不得使用。枚举值见[共享契约 Schema](../../packages/contracts/schemas/platform-v1.schema.json)。
- 不得以 PID 扫描、窗口关闭、裸退出码单独作为完整停止回执。

### 2.3 凭据与私有存储

- 默认使用各平台批准的系统保险库，大型载荷使用批准的加密信封并将密钥存入保险库。Windows Credential Manager、Linux Secret Service、macOS Keychain 等方案须按规格选择并验证。保险库锁定、不可用或故障时须失败关闭，禁止明文回退。
- 仅受管理的无桌面 Linux 服务可逐次显式选择 `restricted-file` 并确认其不提供静态加密。须使用专用非 root UID 与外置持久卷，核验卷和所有者、`0700` 私有目录与 `0600` 密钥文件。桌面没有此入口，保险库故障不得触发切换。此模式不授予设备 `MANAGED` 信任。参见[显式服务文件模式](../../docs/runtime-credentials.md#显式服务文件模式--explicit-managed-file-mode)。
- Darwin 等平台须考虑扩展 ACL 等超出简单 `0600` 的威胁。
- Cookie / 密钥文件权限与所有者检查须在目标 OS 验证；不要假设 POSIX 权限模型处处成立。

### 2.4 文件系统与路径

- 拒绝路径穿越与任意链接跟随（按平台规则）；Mac `.app` 内符号链接策略须显式设计，禁止全局放开。
- 路径长度、socket 路径上限、换行符（LF/CRLF）差异须在原生与测试中显式处理。
- 私有日志 FD / 目录 fd 相对操作等能力缺失时失败关闭，不得 silently 退回不安全 API。

### 2.5 能力声明

- Runtime 须声明平台、架构与停止范围等能力；服务端按声明校验正回执，不远程「重做」OS 事实。
- 缺能力则 doctor/ready 失败，不得带病领取浏览器任务。

### 2.6 检查清单

- [ ] 变更在目标 OS/架构有对应证据或明确未验证声明
- [ ] `processStopScope` 与平台匹配
- [ ] 凭据与私有文件无明文 fallback
- [ ] 如使用 `restricted-file`，已验证显式确认、专用 UID、外置持久卷和私有文件保护，并说明不提供静态加密
- [ ] 业务浏览器沙箱证据覆盖目标平台，并独立于 Electron 界面沙箱证据
- [ ] 未用跨平台假设掩盖路径/权限/进程差异
