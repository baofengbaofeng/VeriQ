# Documentation, contract, and API compatibility standard

规定规格、ADR、用户文档与跨语言契约的维护方式，保证「实现 / 类型 / 样例 / 文档」一致。
约束公共 HTTP、IPC 与结果协议的变更方式，保证客户端、Runtime 与外部调度可安全演进。

## 1. 文档分层

| 层级 | 用途 | 变更规则 |
| --- | --- | --- |
| `AGENTS` / 本规则集 | 长期约束与协作 | 谨慎变更；需协调者/用户确认 |
| `docs/specs/*` | 产品与平台行为规格 | 行为变更先改规格再实现 |
| `docs/decisions/*` | ADR：选型与基线 | 依赖/架构锁定变更必须有 ADR |
| `docs/plans/*` | 实施与接续 | 不替代规格；不写入 AGENTS |
| `docs/*.md` 操作说明 | 开发、发行、离线、AI 等 | 与代码同步；禁止写过期命令充数 |
| `packages/contracts` | Schema / OpenAPI / 生成类型 / 样例 | 单一事实来源；禁止手改生成物充数 |

## 2. 命名与文档诚实性

- 人类可读产品名统一为 **VeriQ**；技术标识小写。
- 规格、计划、API/GUI 标题、生成文档中的产品名大小写不得写成 `veriq` 充作品牌名。
- 日志与对外错误码可用英文；中文用户文档保持术语表一致（Workspace、Run、Attempt、Runtime 等保留约定译法或原文）。
- 计划中的命令须实际跑通后才可标为「已验证可用」。
- 不得删除已知限制来制造「文档上已完成」。
- 进度类内容只放 plans/milestones，不写入 AGENTS 类长期契约。
- 示例配置不得包含真实密钥，须使用明显的假数据。

## 3. 源契约与生成流程

- 对外契约以 `packages/contracts` 的 Schema / OpenAPI 为准。设备内部协议（claim / heartbeat / events / artifact-upload / finish）与结果导入协议同属受控契约面。
- 禁止在 handlers 或客户端手写与契约漂移的「临时字段」，也禁止只改一侧手写类型或只改实现而不更新契约。

1. 先改 Schema / OpenAPI 源（及必要的规范叙述）。
2. 运行正式 generate，更新 Python / TS 生成类型与样例。桌面派生 Schema 与主契约保持同步生成，禁止长期分叉。
3. 同步 Python / TS 校验与兼容测试。
4. 更新 `docs/contracts.md` 或引用该契约的规格段落。

## 4. 版本与兼容性等级

- 资产、引擎、协议、`schema_version` 等身份字段变更须可审计，不得静默复用旧版本号。
- 破坏性 API 变更优先通过新路径或显式版本协商，禁止静默修改旧路径语义。

| 变更类型 | 示例 | 要求 |
| --- | --- | --- |
| 可加性 | 新增可选字段、新增枚举值（旧客户端可忽略） | 须更新契约与样例，并注明忽略策略 |
| 行为收紧 | 更严格校验、失败关闭更严 | 须在规格中说明，并评估旧客户端及旧 Runtime |
| 破坏性 | 删字段、改类型、改鉴权、改幂等语义 | 须单独批准，采用版本策略或并行窗口，说明迁移策略，并在审查中显式标出 |

- 服务端默认忽略未知字段，规格明确要求拒绝时除外。客户端不得因多余字段崩溃。
- 新增枚举值须保证前进兼容。删除枚举值或改变其含义视为破坏性变更。

## 5. 鉴权与作用域

- 每个新端点声明身份类型（用户会话 / 服务令牌 / 设备令牌）与 Workspace 作用域。
- 维护与触发接口保持幂等、有界，响应包含处理计数与 `hasMore`（若适用）。
- 禁止新增无认证「调试后门」。临时探针不得进入发行分支。

## 6. 错误与分页

- 错误码须稳定且可文档化。错误码集合变更按兼容性等级处理。
- 列表接口使用统一分页约定，禁止无界全量拉取作为默认生产路径。

## 7. IPC 与本地协议

- Electron preload API 视为公共契约。新增通道须类型化、校验参数与 sender，并有负例测试。
- 本地协议变更不得要求无文档的双端同时热改，应可检测版本不匹配并失败关闭。

## 8. ADR 要求

以下变更必须新增或更新 ADR：

- 锁定依赖族或关键钉死版本（Tornado、Router、Playwright、Electron、Node 等）
- 安全机制（签名、凭证存储、IPC 模型）
- 平台停止语义或进程模型
- 发行管道与静态资源入库方式

ADR 应写清背景、决策、后果与替代方案，状态（selected / superseded 等）须真实。

## 9. 检查清单

- [ ] 行为变更已落到规格或 ADR（如需要）
- [ ] Schema / OpenAPI 源、生成物（含生成类型和桌面派生 Schema）、实现与样例一致
- [ ] 已判定兼容性等级并说明旧客户端和旧 Runtime 的影响。破坏性变更已单独批准，且有迁移策略
- [ ] 鉴权与 Workspace 作用域完整
- [ ] 产品名与术语符合约定
- [ ] 无密钥、无把进度写入长期契约文档
