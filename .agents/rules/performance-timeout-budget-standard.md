# Performance and timeout budget standard

行宽口径：源码及注释每个物理行最多 **120 个显示列**，与 IDE 的 120 列标尺一致。
中文及其它全角/宽字符占 2 列，ASCII 占 1 列；缩进、标点和注释分隔符均计入。
注释长度只统计有效正文的 Unicode 字符，不含缩进与注释符号。
独立单行及块注释首行有效正文为 40～120 字符；块注释续行不设 40 字符下限。

用明确的并发上限、超时与批次预算约束实现，避免无界等待、资源耗尽与「靠睡一会儿」的假稳定。

## 1. 产品默认容量（必须遵守）

| 预算项 | 默认值 | 说明 |
| --- | --- | --- |
| 未结束 Run | 10 | 超出须拒绝或按重叠策略处理，不得静默无限排队膨胀 |
| 在线全局浏览器上下文 | 4 | 控制面调度上限 |
| 单 Workspace 浏览器上下文 | 2 | 空间隔离上限 |
| 离线本机并发 | 1 | 本机离线执行 |
| 心跳 | 10s | Agent → 控制面 |
| 租约 | 60s | 过期失效，不得复活执行权 |
| Playwright retries | 0 | 产品路径 |
| 整用例重试 | ≤1 | 由 VeriQ 编排；通过则为 `UNSTABLE` |

变更上述默认值须规格/ADR 批准，并同步契约、配置校验与测试。

## 2. 超时设计原则

- 每个可能阻塞的 I/O、锁等待、子进程、浏览器操作、HTTP 出站调用必须有**显式超时**与超时后的失败关闭路径。
- 禁止用固定 `sleep` 充当同步或「等待系统稳定」。
- 超时后必须区分：可重试瞬时失败 vs 不可重试 vs 停止/副作用未知（未知则隔离，不盲目重试）。
- 多层超时应有包含关系：外层（Attempt/租约）≥ 内层（单步/单次 HTTP）；禁止内层无限、只靠外层租约碰巧打断且无清理。

## 3. 建议预算类别（实现时落到配置/常量并文档化）

具体毫秒数可按环境配置，但**类别不可缺失**。新增调用须归入一类并写明默认值来源。

| 类别 | 典型对象 | 要求 |
| --- | --- | --- |
| 控制面入站 | API 处理器、SSE 写 | 避免单请求占满事件循环；大响应流式或分页 |
| 控制面出站 | AI Provider、S3、Webhook | 明确 connect/read 超时与最大重试次数 |
| DB | 查询、事务、迁移锁 | 长事务禁止；维护用有界批次 |
| 队列/维护 | lease reap、cleanup、expire | 批次大小有界；返回 `hasMore` |
| Runtime 本机 | 编译、安装依赖、启动浏览器 | 超时后终止并进入停止/隔离状态机 |
| 浏览器/用例 | 导航、断言、fixture | 使用 Playwright 条件等待；禁止无界 wait |
| 桌面 IPC | preload 调用 | 渲染进程等待有超时；失败可展示且不卡死 UI |
| 停止收尾 | Worker/Chrome 退出观察 | 有截止时间；超时 → 不确定 → 隔离，不假装成功 |

## 4. 资源与背压

- 队列与上传须有背压：拒绝、延迟或 `hasMore`，禁止无限缓冲导致 OOM。
- 制品与日志磁盘占用受保留期与容量配置约束；写满时失败关闭并告警，不得静默丢关键证据却报 PASSED。
- 浏览器上下文创建失败（触达上限）须返回明确错误，不得卡住 claim 循环。

## 5. 性能相关变更纪律

- 以可测量数据为依据（耗时、队列深度、失败率）；禁止无基准的「优化」大改。
- 不得为吞吐牺牲：鉴权、fencing、签名校验、停止证明。
- 热点路径避免 N+1 查询与无索引过滤；必要索引随迁移落地。

## 6. 测试要求

- 容量上限与拒绝路径有测试。
- 关键超时路径有测试（至少：出站超时、停止观察超时、维护批次边界）。
- 性能测试若作为门禁，须固定环境与版本；波动不得靠重试到绿解决。

## 7. 检查清单

- [ ] 新阻塞点有超时与失败关闭
- [ ] 未引入 sleep 同步或无界缓冲
- [ ] 容量/租约默认值未被静默改动
- [ ] 超时与背压有可观察日志/指标字段
