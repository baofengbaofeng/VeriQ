# API compatibility and evolution standard

行宽口径：源码及注释每个物理行最多 **120 个显示列**，与 IDE 的 120 列标尺一致。
中文及其它全角/宽字符占 2 列，ASCII 占 1 列；缩进、标点和注释分隔符均计入。

约束公共 HTTP/IPC/结果协议的变更方式，保证客户端、Runtime 与外部调度可安全演进。

## 1. 单一事实来源

- 对外契约以 `packages/contracts` 的 Schema / OpenAPI 为准，生成 Python/TS 类型与样例。
- 禁止在 handlers 或客户端手写与契约漂移的「临时字段」。
- 设备内部协议（claim / heartbeat / events / artifact-upload / finish）与结果导入协议同属受控契约面。

## 2. 兼容性等级

| 变更类型 | 示例 | 要求 |
| --- | --- | --- |
| 可加性 | 新增可选字段、新增枚举值（旧客户端可忽略） | 须更新契约与样例；注明忽略策略 |
| 行为收紧 | 更严格校验、失败关闭更严 | 须规格说明；评估旧客户端/旧 Runtime |
| 破坏性 | 删字段、改类型、改鉴权、改幂等语义 | 须版本策略或并行窗口；单独批准 |

- 未知字段：服务端默认忽略（除非规格要求拒绝）；客户端不得因多余字段崩溃。
- 枚举：新增要可前进兼容；删除或改含义视为破坏性。

## 3. 版本与标识

- 资产、引擎、协议、schema_version 等身份字段变更须可审计，不得静默复用旧版本号。
- 破坏性 API 变更优先通过新路径或显式版本协商，而不是偷偷改旧路径语义。
- 桌面派生 Schema 与主契约保持同步生成，禁止长期分叉。

## 4. 鉴权与表面最小化

- 每个新端点声明身份类型（用户会话 / 服务令牌 / 设备令牌）与 Workspace 作用域。
- 维护与触发接口保持幂等、有界；响应包含处理计数与 `hasMore`（若适用）。
- 不新增无认证「调试后门」；临时探针不得进入发行分支。

## 5. 错误与分页

- 错误码稳定、可文档化；变更错误码集合按兼容性等级处理。
- 列表接口使用统一分页约定；禁止无界全量拉取作为默认生产路径。

## 6. IPC 与本地协议

- Electron preload API 视为公共契约：新增通道须类型化、校验参数与 sender，并有负例测试。
- 本地协议变更不得要求无文档的双端同时热改；应可检测版本不匹配并失败关闭。

## 7. 检查清单

- [ ] Schema/OpenAPI/生成类型/样例已同步
- [ ] 兼容性等级已判定；破坏性有批准与迁移策略
- [ ] 鉴权与 Workspace 作用域完整
- [ ] 旧客户端/旧 Runtime 影响已说明
