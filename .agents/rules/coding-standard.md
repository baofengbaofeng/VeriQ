## 1. 格式与工具

- 缩进：可编程源码一律 **4 个空格**；禁止 Tab（`.editorconfig` 明确例外除外，如 `Makefile`）。
- 源码须遵守[显示列宽硬上限](#11-显示列宽的统一计算)。Prettier 的 `printWidth: 120` 只是排版目标，硬上限由显示列宽检查器判定。
- 字符集与换行：UTF-8、LF、文件末换行；遵守仓库根 `.editorconfig`。
- Python：静态检查使用 pylint，并配合 pylintrc；格式化使用 Black 或 Pyink。风格细节遵循《Python 编码规范》。
- TypeScript/JavaScript：以 Biome / Prettier / `tsc` 为准；风格细节遵循《TypeScript/JavaScript 编码规范》。
- C/C++ 原生代码：4 空格；与所属平台 native 模块既有风格保持一致，新增文件不得引入 Tab。
- 禁止为「临时」或「占位」代码另立宽松格式标准。

### 1.1 显示列宽的统一计算

源码及注释每个物理行最多 **120 个显示列**，与 IDE 中等宽字体的 120 列标尺采用同一口径。
显示列数与 Unicode 字符个数、UTF-8 字节数和 JavaScript UTF-16 长度分别计算。

- ASCII 和普通窄字符占 1 列；中文及 Unicode East Asian Width 为 W/F 的字符占 2 列。
- 组合附加符号（Mn/Me）与格式字符（Cf）不额外占列；模糊宽度 A 按 1 列。
- 行首缩进、标点、引号、注释分隔符都计入；换行符不计入。
- Tab 推进到下一个 4 列制表位，但不得用 Tab 绕过既有的空格缩进要求。
- `// ` 加 59 个汉字是 121 列，必须换行；60 个汉字正文恰好是 120 列。
- 代码、注释、docstring、导入语句和生成源码均适用，不能用禁用检查或转义中文来隐藏超限。

运行 `python3 scripts/line_width.py` 或 `pnpm lint:width` 检查全仓源码。
检查范围包括测试、夹具、构建脚本、原生代码和安装脚本；生成源码须修正生成器并重新生成。
Markdown 正文、数据 Schema、依赖锁文件和第三方依赖不属于此源码扫描范围。
这些文件中的源码示例仍须在编写和审查时遵守同一列宽口径。

Prettier、Black/Pyink、Ruff 的行宽参数只是排版目标，不能保证长注释和字符串符合显示列上限。
不得通过 IDE 自动软换行冒充源码已换行；超限必须在源码中实际断行。
注释行适用同一上限，超出部分须换行。代码应在合法语法边界断行。字符串须保持运行时内容，不能给 SQL、快照或模板引入换行。

### 1.2 注释正文长度

注释长度只统计去掉缩进、注释分隔符、行前缀和首尾空白后的有效正文，与显示列数分别计算。
独立单行注释及每个注释块的首行有效正文为 **40～120 个 Unicode 字符**。块注释续行不设 40 字符下限。
必须同时满足正文长度与[整行显示列宽](#11-显示列宽的统一计算)。不得凑字、填空白或删除关键说明来满足机械检查。

## 2. 命名与标识

- 产品名人类可读形式为 **VeriQ**；技术标识保持小写：`veriq`、`@veriq/*`、`veriq_server`。
- Python：模块/包/函数用 `snake_case`；类用 `PascalCase`；常量用 `UPPER_SNAKE_CASE`（与 PY 指南一致）。
- TypeScript：遵循 TS 指南的命名约定；导出符号须可被公开 API 注释与契约生成覆盖。
- 数据库表：一律 `veriq_` 前缀；迁移版本表 `veriq_alembic_version`。
- 进程名：`veriq` / `veriq_agent` / `veriq_runner`（CLI 可 `veriq_cli`）须对应真实 OS 进程名。

## 3. 注释（中文）

- 源码注释（模块说明、公开 API 文档串、关键路径旁注）一律**中文**；产品名与技术标识可保留原文。
- 注释覆盖率必须 **> 40%**（注释行 / (注释行 + 非空代码行)）；仅排除生成物与 vendored 依赖。
- 每条注释解释**此处**职责、不变量、失败关闭点或非显而易见取舍；禁止套话灌水。
- 公开方法、公开类、公开接口/类型、导出函数必须有中文注释；核心分支与执行路径须覆盖。
- 独立单行注释及块注释首行有效正文须含中文。注释须遵守[正文长度](#12-注释正文长度)与[显示列宽](#11-显示列宽的统一计算)要求，禁止空洞短标题与无信息填充。
- 测试注释以行为说明为主，不要灌水。
- 机械检查：`scripts/comment_audit.py`（正文/覆盖率）、`scripts/comment_blocks.py`（块排版）与 `scripts/line_width.py`（显示列宽）。自动通过不代替人工质量审查。

在仓库根运行 `uv run --project apps/srv --frozen --no-sync python scripts/comment_audit.py --output /tmp/veriq-comment-audit.json`。
注释审计独立于 `pnpm lint`。报告须覆盖全部应计源码，注释覆盖率严格大于 40%，并通过正文检查。

经成熟解析器确认上下文且有实际工具行为证据的固定词元按功能代码计量，贡献 `C=0`，原文保留在非空物理代码行 `K`。
词元和同行普通说明均须满足显示列宽，普通说明继续独立计量和检查正文。排版器保留的 pragma 前缀没有计量效力。
已支持词元和资格条件见[工具语法计量 ADR](../../docs/decisions/0028-工具语法计量.md)、[行尾类型检查指令计量 ADR](../../docs/decisions/0030-行尾类型检查指令计量.md)和[可信注释解析器 ADR](../../docs/decisions/0026-可信注释解析器.md)。

### 3.1 独立块注释的固定形状

C 风格的独立文档块始终将开闭分隔符各自放在一行，即使原先能放进单行也须展开。
正文从下一行的 ` * ` 开始；空正文段落使用 ` *`。分隔符与周围代码保持同级缩进。
普通独立 `/*` 说明块及 `/*!` 许可块也遵守相同形状，并保留各自的开头标记。

```ts
/**
 * 使用真实临时文件验证导出副本在成功、取消及查看器失败后均被回收，同时保证原始证据字节不受影响。
 * 续行可以更短，不能为凑够字符数而填充空话。
 */
```

禁止让正文紧随 `/**`，或让 `*/` 与最后一句正文共用一行。
“首行正文”是上例的第一条有效说明，不能把独占分隔符行当作长度不足的注释。
Python 的 `#` 和三引号文档串保持本语言语法，不改成 C 风格块。
行内类型注解、编译器/格式化指令等工具语法保持原位置，避免自动分号或指令语义变化。
字符串、模板、正则及有意测试注释文本的夹具内容不属于源码真实注释，不能靠正则全文替换。

在仓库根运行 `pnpm lint:comments`，通过锁定的 Python 环境调用 `scripts/comment_blocks.py` 检查所有源码中的此类块。
生成源码也须检查；修复生成器并重新生成，禁止手改生成文件。
块排版与正文长度、内容质量、注释覆盖率分别检查，不能用新增分隔符空行抬高覆盖率。

## 4. 日志（英文）

- logger、诊断 print、结构化 log event 的 message 字段必须使用**英文**。
- 请求体、领域数据、用户输入中的其它语言可以原样保留。
- 禁止在日志中输出密钥、token、Cookie、密码、完整凭证或未脱敏的隐私字段。

## 5. 错误处理与失败关闭

- 关键路径失败关闭（fail closed）：授权失败、租约/fencing 失效、停止证明不确定、签名校验失败等，不得「尽量继续」。
- 禁止宽泛 `except Exception` / `catch (e)` 后静默吞掉；若必须捕获，须记录英文日志并明确降级或失败语义。
- 不确定状态须进入隔离/人工恢复路径，不得伪造成功。

## 6. 生成物与不可变产物

- DSL 可编辑；由编译器生成的 TypeScript 等产物视为**不可变**，禁止手改后当作源码提交（除非任务明确是调整生成器并重新生成）。
- 契约生成文件（如 `*.generated.ts`）只能通过正式 generate 流程更新，并与 Schema/OpenAPI/样例一并提交。
- 前端生产静态资源经 stage 进入 `apps/srv/src/veriq_server/static/dist`；不得把密钥打进前端产物。

## 7. 依赖与复用

- 优先成熟第三方库；禁止自研密码学、浏览器等待、Cron、schema/迁移框架、通用报告引擎。
- 新增依赖须符合[依赖与许可](#14-依赖与许可)，并与锁定工程基线一致。

## 8. 检查清单（提交前）

- [ ] 缩进与 `.editorconfig` 一致
- [ ] 已运行显示列宽检查，代码、导入与注释的每个物理行均符合[显示列宽要求](#11-显示列宽的统一计算)
- [ ] 触及语言的 lint/format/typecheck 已通过
- [ ] 公开 API 与关键路径有合格中文注释，符合[正文长度](#12-注释正文长度)及[显示列宽](#11-显示列宽的统一计算)要求
- [ ] 涉及源码或计量工具时，已独立运行注释审计，报告计量完整，注释覆盖率严格大于 40%，正文检查通过
- [ ] 日志为英文且无敏感信息
- [ ] 未手改不可变生成物；契约变更已重新生成
- [ ] 未引入与 PY/TS 指南或本总则冲突的风格例外

## 9. 架构边界与扩展性

固定模块职责与依赖方向，使新功能可扩展而不侵蚀控制面/执行面分离。

### 9.1 分层与方向

主要源码依赖方向如下。

```text
apps/web、apps/desktop → packages/ui、packages/contracts
apps/desktop → apps/web、apps/runtime
apps/desktop → packages/compiler、packages/runner-sdk
apps/runtime → packages/compiler、packages/runner-sdk、packages/contracts
packages/compiler、packages/runner-sdk → packages/contracts
```

HTTP 调用方向如下。

```text
Web、桌面宿主 → apps/srv（平台 API）
云端 Runtime、桌面 Agent → apps/srv（领取、心跳、回报）
apps/srv → 获批 HTTP 数据源
Runtime 执行引擎 → 被测系统及其 fixture 服务
```

- 控制面在 Python 中校验共享 Schema，不依赖前端或执行包运行。HTTP 调用方与服务端按契约交互。
- 控制面 **不得** 依赖 Playwright、Chrome、Electron、桌面原生模块才能启动或完成核心 API。
- Web/Desktop UI **不得** 直连数据库或读取服务端私有密钥存储。
- `packages/contracts` 保持无业务副作用；生成类型可被各端依赖，但契约包不反向依赖 apps。
- 禁止为图省事引入循环依赖（例如 runtime ↔ srv 共享可变单例）。

### 9.2 职责边界

| 模块 | 应做 | 不应做 |
| --- | --- | --- |
| `apps/srv` | 认证、Workspace、队列、契约校验、静态托管、获批 HTTP 数据源读取 | 跑浏览器测试、内嵌 Node 执行引擎 |
| `apps/runtime` | 领取任务、编译执行、本地持久化、停止证明 | 实现第二套结果协议或绕过 fencing |
| `apps/desktop` | GUI、白名单 IPC、本地打包资源与历史报告读取 | 用远程网页代替本地 GUI，或把 Electron Node 当测试引擎 |
| `packages/compiler` | DSL → 不可变 TS | 执行测试或访问用户密钥 |
| `packages/runner-sdk` | 确定性执行与事件 | 产品级重试策略（重试归 VeriQ） |

### 9.3 扩展点偏好

- 新能力优先：契约字段扩展 → 服务适配 → Runtime 能力声明 → UI，而不是先做 UI 假页面。
- 平台差异收敛到 native/adapter 层；共享业务代码不复制成多份「几乎一样」的实现。
- 存储后端（本地文件 / S3 等）以适配器隔离；业务服务不散落 SDK 调用。
- AI Provider 以适配器接入；确定性主路径在无 Provider 时完整可用。

### 9.4 配置与特性开关

- 配置经统一设置加载与校验；禁止散落魔法常量且无文档。
- 特性开关不得绕过授权或签名校验。
- 环境相关 URL、域名约束等属于环境资产，不硬编码进执行快照逻辑之外的随意位置。

### 9.5 代码质量与可扩展性

- 新模块保持小而可测；公共入口有中文注释说明不变量。
- 避免「工具类万能桶」导致边界消失。
- 复制粘贴第三次出现的逻辑应抽到正确层（contracts / domain service / adapter），而不是继续分叉。

### 9.6 检查清单

- [ ] 未把执行引擎依赖引入控制面
- [ ] 依赖方向符合分层；无新的循环依赖
- [ ] 平台差异在适配层；契约先于 UI
- [ ] 扩展未削弱授权/签名/停止等不变量

## 10. 资产编译与不可变产物

约束 DSL、校验、编译、发布与执行快照，保证可复现执行并防止「改生成物」或「跑最新草稿」破坏确定性。

首版只交付联网执行。F12 离线任务、签名离线包的产品交付、离线结果导入及对应验收退出 MVP。生产入口仅提供联网执行、历史离线包元数据和历史报告读取，旧协议及持久数据保留用于兼容。数据集无离线导出例外或管理员开关。适用边界见[契约说明](../../docs/公共契约.md#联网静态数据传输)。

### 10.1 源与产物

| 类型 | 可变性 | 规则 |
| --- | --- | --- |
| DSL / 资源草稿 | 可编辑 | 经校验与权限控制；不直接当作生产执行真源 |
| 已发布版本 | 不可变 | 禁止原地修改；变更走新版本 |
| 编译生成的 TypeScript | 不可变产物 | 禁止手改后提交充源码；只通过编译器生成 |
| 执行快照 | 冻结 | 冻结资产、引擎、环境、数据版本与行键、角色和浏览器等执行身份 |

### 10.2 校验与发布

- 发布前须通过契约/业务校验；失败不得发布。
- 受信编译完成回执须校验设备、租约/fencing、引擎清单与上传完整性（按规格）。
- 禁止把「仅排队成功」当成「已验证发布」。
- 版本内容 hash（如 sha256）必须可核验；篡改即失败关闭。

### 10.3 执行确定性

- Runner 执行已冻结的快照，使用锁定引擎。正式运行使用已发布资产。联网 DEBUG 可使用经可信 Runtime 验证的不可变草稿候选，验证成功后才生成可执行清单。验证失败按真实终态结束，禁止回退到可变草稿或工作区最新文件。详见[统一队列与验证边界](../../docs/decisions/0010-统一队列与围栏执行.md)。
- Playwright 产品路径 `retries=0`。整用例重试及聚合结果按[重试规则](#126-重试)处理。
- 断言真值来自版本化预期，禁止把当次实际值写回并冒充基线（除非明确的基线更新流程且经审核）。

### 10.4 引擎与依赖闭包

- 执行依赖版本化。历史签名离线包的兼容验证继续核对签名、清单、精确闭包与文件摘要，信任根须独立建立。历史验证不开放首版新签发、下载、导入或执行入口。详见[历史离线包的信任边界](../../docs/decisions/0016-离线资源包边界.md)。
- 引擎候选与晋升身份不可覆盖；桌面升级不得静默替换测试引擎。
- Node 24 执行引擎与 Electron 内嵌运行时分离。

### 10.5 Fixture 与数据

- Fixture 准备/清理幂等；崩溃可补偿。
- 业务身份与平台登录身份分离；清理失败影响 outcome（不得无声忽略）。
- 联网执行时静态行正文及 HTTP 映射值经当前授权通道进入受控执行进程内存。生成源码、下载产物、验证与执行工作目录、IPC 持久缓存、SQLite、日志和本地报告均不得存入数据正文。可能回显无法可靠脱敏数据的截图、Trace 或其他证据按任务禁止采集。
- 以冻结版本和摘要校验数据，受控临时内存超限须返回明确错误。正常结束、失败、取消、租约到期和崩溃恢复均须核验清理及进程状态。含正文的历史编译包必须从原冻结依赖重新验证为兼容的联网产物后才可执行。详见[联网静态数据传输契约](../../docs/公共契约.md#联网静态数据传输)。

### 10.6 检查清单

- [ ] 未手改生成 TS 或已发布版本内容
- [ ] 执行路径绑定快照 hash/引擎身份
- [ ] 校验失败与回执失败均失败关闭
- [ ] 涉及历史离线包时已保留闭包与签名校验，未开放首版离线执行、签发、下载或导入路径
- [ ] 联网数据集正文未进入本地持久产物，清理和证据策略符合规格

## 11. 审计与执行事件

约束审计日志、执行事件流与实时通知的完整性、授权与可靠性，支撑追责与可观测性。

### 11.1 审计日志（谁在何时对何物做了什么）

至少覆盖：

- 登录/登出、会话撤销、用户禁用
- Workspace 成员与角色变更、邀请
- 资产发布、归档、权限相关配置变更
- Runtime 授权/撤销、服务令牌创建与作废
- 维护任务触发、证据保留期变更
- 敏感导出。历史离线包签发相关审计保留用于兼容核对，首版不得为补齐审计点恢复签发入口。

要求：

- 记录操作者身份类型、对象 ID、结果及 UTC 时间。Workspace 范围内记录真实 Workspace。登录、登出及安装级事件无 Workspace 时可缺省该字段，不得虚构所属空间或将全局事件写入任意租户。
- 消息英文；不含秘密原文
- 审计写入失败不得导致「操作成功但完全无痕」的默示成功——关键安全操作须失败关闭或同步告警策略（按规格）

### 11.2 执行事件

- Attempt 进度、步骤、断言、取消、失联、停止证明等事件进入统一协议，供报告与 SSE/订阅使用。
- 事件须带顺序/序号或等价单调语义，避免乱序展示为错误归约。
- 订阅与 SSE 必须校验 Workspace 与成员资格；禁止跨空间搭线。
- 客户端断线重连不得重复造成副作用；以服务端状态为准。

### 11.3 可靠性

- 关键终态（finish、取消完成及历史离线导入的保留结果）以持久化状态为权威，事件流为派生视图。
- 允许「事件晚到」但必须与 fencing/幂等规则一致；晚到旧代事件不得覆盖新代。
- 不得为了推送方便而绕过服务层直接改库。

### 11.4 保留与查询

- 审计与执行事件遵循留存策略；查询接口分页且授权。
- 管理员跨空间审计能力若存在，须显式角色与审计自身可追溯。

### 11.5 检查清单

- [ ] 新安全敏感写操作有审计点
- [ ] 事件订阅有 Workspace 校验
- [ ] 乱序/迟到事件不破坏 fencing 与归约
- [ ] 审计与事件无秘密泄漏

## 12. 并发、幂等、状态与超时预算

约束队列领取、租约、fencing、取消与结果写入，降低竞态、重复执行与错误释放容量的风险。
用明确的并发上限、超时与批次预算约束实现，避免无界等待、资源耗尽与「靠睡一会儿」的假稳定。

### 12.1 产品默认预算（必须遵守）

| 预算项 | 默认值 | 说明 |
| --- | --- | --- |
| 未结束 Run | 10 | 超出须拒绝或按重叠策略处理，不得静默无限排队膨胀 |
| 在线全局浏览器上下文 | 4 | 控制面调度上限 |
| 单 Workspace 浏览器上下文 | 2 | 空间隔离上限 |
| 历史离线本机并发 | 1 | 兼容核对时沿用的旧边界，首版不开放离线执行 |
| 心跳 | 10s | Agent → 控制面 |
| 租约 | 60s | 执行权的有效期 |
| Playwright `retries` | 0 | 产品路径 |
| 整用例重试 | ≤1 | 由 VeriQ 编排，见「重试」 |

变更上述默认值须规格/ADR 批准，并同步契约、配置校验与测试。

### 12.2 状态机纪律

- Run / Job / Attempt / 停止证明等状态迁移必须遵循规格中的合法边；禁止跳跃或「顺手改库字段」绕过服务层。
- 业务结果、清理结果、证据完整性、进程停止证明是不同事实，须分别持久化后再归约。
- 结果归约顺序固定：`ERROR > INCOMPLETE > FAILED > CANCELLED > UNSTABLE > SKIPPED > PASSED`。禁止只存最高优先级字符串而丢弃原始事实。

### 12.3 租约与 fencing

- 心跳与租约使用产品默认预算。租约过期即失效，不得复活执行权。
- 领取只分配 `LEASED` Attempt。激活前可经授权下载分配到的制品，以验证不可变闭包。须确认显式激活后才可派生 Worker，或开始业务认证、fixture 和其他业务副作用。用同一 `clientRequestId` 恢复尚未激活的领取时，轮换令牌和 fencing，使旧证明立即失效，且保留原截止时间。已激活的领取返回冲突，不另授执行权。见[统一围栏执行决策](../../docs/decisions/0010-统一队列与围栏执行.md#adr-0010--unified-queue-and-verified-execution-boundaries)。
- 设备身份与租约、fencing 证明有效，但请求者已失去授权时，心跳返回 `cancelRequested` 且不续租。设备身份或租约、fencing 证明无效时，心跳须失败关闭。
- 所有变更执行中状态的写入须校验 lease / fencing；迟到或旧 fencing 的回报必须拒绝或隔离，不得覆盖新代结果。

### 12.4 幂等

- 外部触发、维护批次、制品上传完成回执等须支持幂等键或等价去重。将幂等键绑定已授权主体、作用域与请求内容，使用持久唯一约束和原子事务处理并发。
- 副作用未知时先按业务键或幂等键核对已存状态，继续遵守[重试规则](#126-重试)。单独的先查后写不能充当去重保护。
- 历史离线导入的幂等与来源语义须保留，历史记录不得覆盖在线 Attempt 权威记录。重复导入的安全性仅在历史协议兼容夹具中核对，首版不恢复生产写入路径。

### 12.5 容量、隔离与背压

- 按产品默认预算限制未结束 Run、全局与单 Workspace 浏览器并发。历史离线本机并发仅用于核对旧路径语义。
- 逻辑取消、超时或 PID 不存在都不足以证明进程已停止。停止未确认、失联或进程状态未知时须占用隔离容量，禁止当作空闲释放。
- 仅浏览器任务占用浏览器容量；编译/清理使用各自配额，不得混用导致误限流或误放行。
- 队列与上传须有背压，可拒绝、延迟或返回 `hasMore`。禁止无限缓冲导致 OOM。
- 制品与日志磁盘占用受保留期与容量配置约束。写满时须失败关闭并告警，禁止静默丢关键证据却报 `PASSED`。后续经授权过期的原始证据不改写历史结果或完整性。保留期维护须继续保护固定引用与安全围栏，见[报告证据保留决策](../../docs/decisions/0014-报告与证据存储.md)。
- 达到上限导致浏览器上下文创建失败时须返回明确错误，禁止卡住 claim 循环。

### 12.6 重试

- Playwright 与整用例重试遵守产品默认预算。整用例重试使用新 Context、新 fixture 和新工作目录。
- 首次失败后仅在重试通过时产生 `UNSTABLE` 重试结果。该结果由 Job、CaseExecution 和 Run 汇总，仍按既定优先级保留更严重的结果，默认门禁不通过。保留各次 Attempt 的真实结果，Attempt 不使用 `UNSTABLE`。
- 不可重试错误（鉴权、契约、签名、明确业务断言失败等）不得自动整用例重试。
- 即使是可重试的瞬时失败，自动整用例重试仍须有已声明 fixture 的可信清理成功证明（`cleanupSnapshotSha256`，清理状态 `SUCCEEDED`），或同时具备可信的 `hasPotentialWrites:false` 与 `READ_ONLY_OBSERVED`。证据不足时保留原终态并记录 `RETRY_SAFETY_UNCONFIRMED`。具体准入见[联网执行契约](../../docs/公共契约.md#t10--online-node-agent-and-physical-execution)。
- 副作用未知，或超时后停止状态未知时，禁止盲目重试，以免重复外部写入。
- 超时后须区分可重试的瞬时失败、不可重试失败与停止或副作用未知。超时后停止或副作用未知时须隔离。

### 12.7 超时设计原则

- 每个可能阻塞的 I/O、锁等待、子进程、浏览器操作、HTTP 出站调用都必须有**显式超时**和超时后的失败关闭路径。按「重试」判定是否可重试，按「容量、隔离与背压」处理停止未确认的容量。
- 禁止用固定 `sleep` 充当同步或「等待系统稳定」。
- Attempt 总预算与单步或单次 HTTP 超时应有包含关系，并为收尾保留有界时间。在线租约是由有效心跳续期的独立授权窗口，不是 Attempt 的总时限。Runtime 使用单调时钟看门狗，在租约到期或取消后停止并清理。内层操作须有自己的上限和清理路径，不能只靠租约中断。见[统一队列与验证边界](../../docs/decisions/0010-统一队列与围栏执行.md)和[Agent 监督](../../docs/decisions/0011-执行代理监督.md)。

### 12.8 超时预算类别

实现时须落实到配置或常量并文档化。具体毫秒数可按环境配置，但**类别不可缺失**。新增调用须归入一类并写明默认值来源。

| 类别 | 典型对象 | 要求 |
| --- | --- | --- |
| 控制面入站 | API 处理器、SSE 写 | 避免单请求占满事件循环，大响应流式或分页 |
| 控制面出站 | AI Provider、S3、Webhook | 明确 connect/read 超时与最大重试次数 |
| DB | 查询、事务、迁移锁 | 禁止长事务，维护用有界批次 |
| 队列/维护 | lease reap、cleanup、expire | 批次大小有界，返回 `hasMore` |
| Runtime 本机 | 编译、安装依赖、启动浏览器 | 超时后终止并进入停止/隔离状态机 |
| 浏览器/用例 | 导航、断言、fixture | 使用 Playwright 条件等待，禁止无界 wait |
| 桌面 IPC | preload 调用 | 渲染进程等待有超时，失败可展示且不卡死 UI |
| 停止收尾 | Worker/Chrome 退出观察 | 有截止时间，观察超时按停止未确认处理 |

### 12.9 并发安全实现要求

- 领取与容量扣减须在数据库事务中原子完成；依赖 MySQL 能力（如 `SKIP LOCKED`）时，doctor/迁移入口须拒绝不支持环境。
- 禁止用「先读后写无版本」更新共享计数或 Attempt 终态。
- 本地 SQLite / 文件锁路径须处理崩溃恢复与代际 CAS，不得假设进程永不死亡。

### 12.10 性能相关变更纪律

- 以可测量数据为依据（耗时、队列深度、失败率），禁止无基准的「优化」大改。
- 不得为吞吐牺牲鉴权、fencing、签名校验或停止证明。
- 热点路径避免 N+1 查询与无索引过滤，必要索引随迁移落地。

### 12.11 必测负例与性能测试

- 双 claimer 竞争同一 Job
- 租约过期后的迟到 finish
- fencing 旧值上报
- 取消与完成乱序
- 重复触发。历史离线导入的去重和在线记录保护在兼容夹具中核对。
- 停止证明缺失时容量未释放
- 容量上限与拒绝路径
- 关键超时与边界路径，至少覆盖出站超时、停止观察超时和维护批次边界

性能测试若作为门禁，须固定环境与版本，禁止靠重试到绿掩盖波动。

### 12.12 检查清单

- [ ] 状态迁移经服务层且合法
- [ ] lease/fencing/幂等已覆盖写入路径
- [ ] 不确定停止不释放容量
- [ ] 竞态与乱序负例有测试
- [ ] 新阻塞点有超时与失败关闭
- [ ] 未引入 `sleep` 同步或无界缓冲
- [ ] 容量、心跳、租约与重试默认值未被静默改动
- [ ] 超时与背压有可观察日志/指标字段

## 13. 数据库与迁移

约束 MySQL 模式设计、Alembic 迁移与数据完整性，保障可演进与生产安全。

### 13.1 命名与存储约定

- 全部平台物理表以 `veriq_` 开头；Alembic `version_table = "veriq_alembic_version"`。
- 平台实体 ID 使用 UUID 字符串。物理主键按已批准的领域键设计，关联表可用组合键，内容寻址可使用 Workspace 与摘要的组合键，安装单例可使用固定内部键。时间戳存 UTC（`DATETIME(6)` 量级按规格），显示默认 Asia/Shanghai。
- InnoDB + utf8mb4；连接 `time_zone='+00:00'`。
- UUID 与机器 key 使用区分大小写的排序策略；普通文本使用已声明的 Unicode 排序。
- 业务状态、租约等用独立列，DSL、快照和差异用 JSON。禁止把关键检索条件只塞进无法索引的大 JSON，规格另有明确规定时除外。联网执行的本机持久数据边界见[Fixture 与数据](#105-fixture-与数据)。

### 13.2 完整性与约束

- 空间内唯一性、版本号、幂等键、Attempt 内步骤断言等唯一约束必须在库层落地，不能只靠应用「碰巧」。
- 跨资源引用除 FK/组合约束外，须有服务层 Workspace 归属校验。
- 普通资源归档不随意释放业务 key（遵循规格）。
- 禁止无 Workspace 作用域的「全局可猜 ID 即读写」。

### 13.3 迁移纪律

- 只通过 Alembic 变更模式；禁止生产手工改表后补迁移。
- 迁移须可重复执行于干净库与有数据库；破坏性变更提供扩展表/双写/回填策略说明。
- 长锁、全表重写、大表无索引上线须在审查中显式标出风险。
- doctor/迁移入口拒绝不支持 `SKIP LOCKED` 等队列前提的旧 MySQL。
- 迁移与 ORM 模型、契约中的持久化字段描述保持一致。

### 13.4 事务与并发

- 队列相关事务使用规格要求的隔离级别（如 READ COMMITTED）并测试死锁重试。
- 领取、容量、fencing 更新必须原子；禁止应用层先查后改无保护。
- 大维护任务用有界批次 + `hasMore`，禁止一次事务扫全表无限运行。

### 13.5 数据安全

- 密钥材料不进明文业务表；凭证用 secret 引用/版本模型。
- 备份与导出须考虑敏感字段；日志与异常不得打印连接密码。
- 测试库可重建；禁止把生产转储未脱敏直接提交或用于共享夹具。

### 13.6 本地与离线存储

- Runtime 本地 SQLite 表仍用 `veriq_` 前缀与受限文件权限。联网流程可以持久保存任务状态和授权报告，禁止持久化执行数据集正文。历史本地记录限兼容读取、核对及按规格清理。
- 本地库崩溃恢复、WAL/同步模式与代际 CAS 按既有 ADR/实现约定，不得随意改成「关闭安全选项换速度」。

### 13.7 检查清单

- [ ] 新表/列命名、UTC、平台实体 UUID 与已批准物理主键约定正确
- [ ] 唯一约束与归属校验到位
- [ ] 迁移可审阅、可回滚或有显式风险说明
- [ ] 队列/容量路径具备原子性

## 14. 依赖与许可

规定第三方依赖的选取、钉死、许可兼容与变更流程，降低供应链与合规风险。

### 14.1 总原则

- 仓库许可证为 **AGPL-3.0**；不得擅自更换项目许可证。
- 优先成熟、维护活跃、文档清晰的库；禁止重复造轮子实现密码学、浏览器等待、Cron、迁移框架、通用报告引擎。
- 产品依赖禁止 `latest` 或无上界的浮动主版本；保持精确钉死。
- JavaScript 使用 pnpm workspace。根 `package.json` 锁定 pnpm **11.25.0**，`pnpm-workspace.yaml` 保留 `saveExact`、严格 engine/peer 与获批的安装策略。CI 与发行使用冻结锁文件安装。
- Python：只在 `apps/srv/pyproject.toml` 声明控制面依赖，并以对应锁文件解析。

### 14.2 许可兼容

| 倾向 | 说明 |
| --- | --- |
| 通常可接受 | MIT、Apache-2.0、BSD 等宽松许可（仍须记录） |
| 需审慎评估 | GPL/LGPL 等 copyleft；确认分发与链接义务是否可接受 |
| 网络 copyleft | AGPL 依赖引入须特别审查是否扩大传染面 |
| 禁止默认合入 | 未知许可、专有不可分发、缺失许可证 |

新增或升级前须在 ADR 中记录包名、精确版本、声明许可、用途边界及安全理由，包括已知高危漏洞的核查结果。未知或自定义许可必须事先获批。

### 14.3 安全与维护信号

- 不得引入受尚未修复的高危或严重 CVE 影响的依赖。记录公告适用性和缓解情况，缓解措施不构成放行适用且未修复漏洞的例外。详见[安全规范](./security-standard.md)。
- 偏好近期有维护、issue 有响应的包；对长期停滞项目需书面理由。
- 注意传递依赖风险；锁文件变更须审阅传递树中的异常新增。
- 放宽最小发布年龄、停用完整性校验或 engine/peer 严格模式，均须书面批准和 ADR。生命周期脚本仅按已批准的允许列表开放。

### 14.4 与锁定基线的关系

下列族的移动须用户/协调者批准并更新 ADR：

- Python 3.12、Tornado 6.6.1、SQLAlchemy 2、MySQL 8.4
- React 18、Vite 6、Tailwind 3、react-router-dom 7.18.5
- Node 24、精确 pnpm 11.25.0、Playwright 引擎身份
- Electron 与桌面打包工具链

补丁级更新同样须事先记录 ADR、运行相关测试，并在提交说明中写清动机（安全修复或缺陷修正）。触及锁定基线的更新一并取得显式批准。

### 14.5 变更流程

1. 明确需求与是否已有仓库内可复用依赖。
2. 评估许可、漏洞、维护、传递依赖体积与平台支持。在变更前记录 ADR，锁定基线或需特批的许可按上文取得批准。
3. 写入精确版本；更新锁文件。
4. 同步锁定基线记录及受影响的 `THIRD_PARTY_NOTICES` / SBOM 流程输入。
5. 跑相关 `check`/`test`；说明是否影响 Runtime 闭包或 wheelhouse。

### 14.6 禁止事项

- 整站 fork 第三方应用代码充数
- 把未锁定的系统全局包当作产品依赖
- 用 Electron 内嵌 Node 冒充独立 Node 24 执行引擎身份
- 在前端产物或离线包中夹带未声明的第三方二进制

### 14.7 检查清单

- [ ] 精确版本已钉死；锁文件已更新
- [ ] 新增或升级前的 ADR 已记录许可、版本及安全理由
- [ ] 无适用且尚未修复的高危或严重漏洞
- [ ] 基线族变更已获批准并有 ADR
- [ ] 相关测试与 SBOM/NOTICE 义务已考虑

## 15. 文档、契约与 API 兼容性

规定规格、ADR、用户文档与跨语言契约的维护方式，保证「实现 / 类型 / 样例 / 文档」一致。
约束公共 HTTP、IPC 与结果协议的变更方式，保证客户端、Runtime 与外部调度可安全演进。

### 15.1 文档分层

| 层级 | 用途 | 变更规则 |
| --- | --- | --- |
| `AGENTS` / 本规则集 | 长期约束与协作 | 谨慎变更；需协调者/用户确认 |
| `docs/公共契约.md` | 对外契约和产品行为 | 行为变更先更新对应契约或 ADR 再实现 |
| `docs/decisions/*` | ADR：选型与基线 | 依赖/架构锁定变更必须有 ADR |
| `docs/validation/*` | 验收与交接 | 不替代契约或 ADR；不写入 AGENTS |
| `docs/*.md` 操作说明 | 开发、发行、离线、AI 等 | 与代码同步；禁止写过期命令充数 |
| `packages/contracts` | Schema / OpenAPI / 生成类型 / 样例 | 单一事实来源；禁止手改生成物充数 |

### 15.2 命名与文档诚实性

- 人类可读产品名统一为 **VeriQ**；技术标识小写。
- 规格、计划、API/GUI 标题、生成文档中的产品名大小写不得写成 `veriq` 充作品牌名。
- 日志消息须使用英文，机器可读错误码使用稳定标识。中文用户文档保持术语表一致（Workspace、Run、Attempt、Runtime 等保留约定译法或原文）。
- 计划中的命令须实际跑通后才可标为「已验证可用」。
- 不得删除已知限制来制造「文档上已完成」。
- 进度与里程碑不写入 AGENTS 类长期契约。
- 示例配置不得包含真实密钥，须使用明显的假数据。

### 15.3 源契约与生成流程

- 对外契约以 `packages/contracts` 的规范 JSON Schema 与 OpenAPI 为准。共享传输定义以规范 Schema 为源，HTTP 路由、鉴权和 API 传输约定以 OpenAPI 为源。设备内部协议（claim / heartbeat / events / artifact-upload / finish）及历史结果导入兼容协议同属受控契约面。后者不代表首版提供导入入口。
- 禁止在 handlers 或客户端手写与契约漂移的「临时字段」，也禁止只改一侧手写类型或只改实现而不更新契约。

1. 先改 Schema / OpenAPI 源（及必要的规范叙述）。
2. 运行 `pnpm contracts:generate`，更新 `packages/contracts/src/types.generated.ts` 与 `packages/contracts/src/api.generated.ts`。涉及桌面允许的操作或其校验引用时，另用 `node apps/desktop/scripts/generate-operations.mjs` 同步 `operations.generated.json`、`operations.generated.ts` 和 `validation.generated.json`。保持显式允许列表，新增服务端端点不自动开放给桌面。
3. 同步共享正反样例以及 Python / TS 校验和兼容测试。Python wheel 打包并加载共享 Schema，用于运行时校验。现有生成命令只生成上述产物，样例和 Python 类型或校验代码按变更同步维护。
4. 更新 `docs/公共契约.md` 或引用该契约的规格段落。

### 15.4 版本与兼容性等级

- 资产、引擎、协议、`schema_version` 等身份字段变更须可审计，不得静默复用旧版本号。
- 破坏性 API 变更优先通过新路径或显式版本协商，禁止静默修改旧路径语义。

| 变更类型 | 示例 | 要求 |
| --- | --- | --- |
| 可加性 | 新增旧消费者已允许的可选内容，或只向明确支持该扩展的消费者发送新值 | 须更新契约与样例，注明兼容策略并验证新旧生产者和消费者组合 |
| 行为收紧 | 更严格校验、失败关闭更严 | 须在规格中说明，并评估旧客户端及旧 Runtime |
| 破坏性 | 删字段、改类型、改鉴权、改幂等语义 | 须单独批准，采用版本策略或并行窗口，说明迁移策略，并在审查中显式标出 |

- 固定结构的请求、响应、IPC 及结果文档按声明的契约拒绝未知字段。已命名的开放映射和业务 JSON 按其 Schema 接受开放字段。处理校验失败时须返回可诊断错误，客户端不得崩溃或冒充成功。
- 新增可选字段、枚举值或联合分支前，须验证已部署的严格消费者能否接受。旧消费者会拒绝时，须通过明确版本或能力协商保持旧传输兼容，或按破坏性变更处理。删除枚举值或改变其含义视为破坏性变更。
- 样例与兼容测试须覆盖未知字段、未知枚举值、联合判别及跨语言校验的一致性。详见[契约与生成决定](../../docs/decisions/0003-工程基线.md#contractsource-and-packaging-decision)。

### 15.5 鉴权与作用域

- 每个新端点须显式声明认证方式与作用域。Workspace 范围端点须验证身份及当前空间授权。安装级或明确批准的公开端点须写明其范围、访问条件及可暴露信息，例如经批准的健康探针。禁止为安装级操作虚构 Workspace。
- 维护与触发接口保持幂等、有界，响应包含处理计数与 `hasMore`（若适用）。
- 禁止新增无认证「调试后门」。临时探针不得进入发行分支。

### 15.6 错误与分页

- 错误码须稳定且可文档化。错误码集合变更按兼容性等级处理。
- 列表接口使用统一分页约定，禁止无界全量拉取作为默认生产路径。

### 15.7 IPC 与本地协议

- Electron preload API 视为公共契约。新增通道须类型化、校验参数与 sender，并有负例测试。
- 本地协议变更不得要求无文档的双端同时热改，应可检测版本不匹配并失败关闭。

### 15.8 ADR 要求

以下变更必须新增或更新 ADR：

- 锁定依赖族或关键钉死版本（Tornado、Router、Playwright、Electron、Node 等）
- 安全机制（签名、凭证存储、IPC 模型）
- 平台停止语义或进程模型
- 发行管道与静态资源入库方式

ADR 应写清背景、决策、后果与替代方案，状态（selected / superseded 等）须真实。

### 15.9 检查清单

- [ ] 行为变更已落到规格或 ADR（如需要）
- [ ] Schema / OpenAPI 源、生成物（含生成类型和桌面派生 Schema）、实现与样例一致
- [ ] 已判定兼容性等级并说明旧客户端和旧 Runtime 的影响。破坏性变更已单独批准，且有迁移策略
- [ ] 已明确认证或公开条件与作用域，Workspace 路径执行当前空间授权
- [ ] 产品名与术语符合约定
- [ ] 无密钥、无把进度写入长期契约文档

## 16. 错误处理与可观测性

提升故障可诊断性与失败关闭一致性，避免静默失败和敏感信息泄漏。

### 16.1 失败关闭优先

- 授权失败、契约校验失败、租约/fencing 失效、停止证明不确定、签名/信任根失败：必须失败关闭，禁止「尽量继续」。
- 部分成功须显式建模（保留业务结果、清理结果、证据完整性等独立事实），不得只留一个含糊的成功布尔值。
- 捕获异常后若无法安全恢复，应向上返回可分类错误，而不是吞掉后返回空成功。

### 16.2 错误模型

- 对外 API：稳定的错误码 / 机器可读 `code` + 安全的人类可读说明；不暴露栈、SQL、本地路径、密钥。
- 对内领域：区分可重试瞬时错误与不可重试逻辑错误；未知业务副作用禁止盲目重放。
- 跨语言（Python ↔ TS ↔ 契约）错误码与结果枚举保持同一事实来源，禁止各端私自发明同义不同码。
- HTTP：未知 API 返回真实 404；认证失败与权限不足语义分离；维护接口对无权限调用不得冒充「无工作可做」。

### 16.3 日志

- 日志 message 使用英文；结构化字段承载 ID、阶段、outcome、scope 等。
- 必带关联字段（按场景）：`workspace_id`、`run_id` / `job_id` / `attempt_id`、`runtime_id`、请求幂等键等——在已具备上下文时不得省略。
- 禁止记录：密码、token、Cookie、Authorization、连接串密钥、未脱敏隐私、离线包私钥材料。
- 同一失败路径须有且仅有清晰的主日志点，避免刷屏重复与完全无日志两种极端。
- 级别：`error` 表示需关注的失败；预期内负例（如权限拒绝）可用 `warning`/`info`，但须可检索。

### 16.4 指标与健康

- 控制面提供独立的 liveness 和 readiness。`/health/live` 只报告进程存活，不依赖数据库。`/health/ready` 检查已纳入就绪条件的关键依赖，数据库故障时返回 `503` / `degraded`，不暴露异常或连接串。见[生产静态托管与健康检查决策](../../docs/decisions/0019-生产静态资源清单.md)。
- 队列、租约回收、维护任务应能观测处理量、`hasMore`、失败计数；禁止只靠人工翻日志判断积压。
- 桌面/Agent 诊断信息可导出，但须脱敏且不自动上传密钥。

### 16.5 用户与运维可见性

- UI/报告须区分：业务失败、清理失败、失联、取消、证据不全、停止未确认等，不得全部显示为「失败」。
- `UNSTABLE`、`INCOMPLETE` 和 `ERROR` 保持契约定义的 outcome。失联为 `ERROR`，并保留 `WORKER_LOST` 原因码。展示须保留结果、原因及停止事实，不得将其合并为普通 `FAILED` 或把原因码当成 outcome。

### 16.6 检查清单

- [ ] 新失败路径有明确码与英文日志，且脱敏
- [ ] 不确定状态进入隔离/失败关闭，而非假成功
- [ ] 跨语言错误/结果枚举已同步契约
- [ ] 关键运维路径可观测（计数或健康信号）

## 17. 出站网络与外部集成

约束控制面/Runtime/桌面发起的外部调用与集成点，防止 SSRF、凭证泄漏与不可控重试风暴。

### 17.1 出站调用清单思维

凡新增强依赖外部系统的能力，须写明：

- 调用方（srv / runtime / desktop）
- 目标类型（AI Provider、对象存储、被测系统、更新源、邮件等）
- 鉴权材料存放位置
- 超时、重试、幂等与失败关闭行为
- 是否可能触及用户内网（SSRF 风险）

### 17.2 SSRF 与 URL 安全

- 由用户或 Workspace 配置的 URL（环境地址、Webhook、Provider Endpoint、制品 URL 等）须按该调用的已批准策略验证协议、来源、连接目标和重定向。链路本地与云元数据目标禁止通过部署配置放开。企业私网仅在具体规范允许的范围内，经显式批准后按目标放行。
- 禁止把未校验的用户 URL 直接交给服务端请求库「代抓」。
- 重定向跟随策略须受限；不得通过跳转绕过允许列表。
- 文件/制品下载路径由服务端生成与鉴权，不接受任意本地路径或未签名外链充作内部制品。
- 联网数据集由控制面通过获批 HTTPS 连接读数据，按配置的数值地址连接，并使用批准域名进行 TLS 校验及设置 Host。企业私网例外仅涵盖明确批准的 RFC1918 或 ULA 目标。禁用重定向和环境代理，只有显式 `retry_reads` 允许 GET 连接失败后重试一次。连接范围、凭据和读取预算见[HTTP 数据源契约](../../docs/公共契约.md#http-数据集定义与预览)。

### 17.3 AI 与第三方 Provider

- 未配置 Provider 时主路径仍可用；测试默认无真实密钥。
- 出站调用受预算、超时与审计记录约束；失败不得拖垮队列。
- 只发送获授权且有界的任务相关脱敏内容。设备 token、数据库密码、业务凭据及其引用、Provider 密钥和原始证据禁止进入模型上下文。Provider 密钥只在批准的传输鉴权边界使用。
- `/ai` 审核与生成流程在发送前预览脱敏上下文，并由用户审核自由输入材料。对话 Agent 的普通轮次按当前成员身份、会话归属和预算发送获准的会话内容与脱敏投影。保存计划或触发运行前须展示结构化提议，由用户明确确认当前已审阅的提议，再复核会话归属、动作权限与提议新鲜度。详见[Workspace 授权](./security-standard.md#3-workspace-授权)。
- 模型输出须通过规范 Schema 和引用校验。边界建议与失败分析仅供人工判断。显式人工接受才可通过资源服务创建或更新 CASE 草稿，并重查权限、修订和引用。资产发布仍由人按既有授权、Runtime 验证及回执流程执行，禁止自动应用、自动发布或在执行时改写断言真值。见[AI Provider 边界](../../docs/decisions/0015-模型服务接入边界.md)和[AI 使用说明](../../docs/模型辅助使用指南.md)。
- Provider SDK 经适配器接入；禁止在业务层散落裸 SDK 调用与硬编码密钥。

### 17.4 对象存储与制品

- S3/兼容存储凭据仅存服务端安全配置；最小权限桶策略。
- 上传完成以服务端校验与清单为准；客户端不得宣称「已上传成功」绕过校验。
- 公共读桶不是默认。下载须检查当前授权与对象归属，设备拉取冻结执行制品还须验证有效的 Attempt 租约、fencing 及闭包成员。按契约使用相应授权机制和适用的短时许可，禁止暴露原始存储键或绕过授权的传输路径。见[制品传输与授权](../../docs/公共契约.md)。

### 17.5 外部调度与 Webhook

- 平台不设内部 Cron；外部调度调用认证 HTTP 接口。
- 入站触发已在 API 规范约束；若做出站 Webhook，须签名/密钥、超时、有限重试与重放防护。
- 重试须幂等；副作用未知时停止重试并告警。

### 17.6 Runtime 访问被测系统

- 被测前后端地址来自环境快照与域名约束；执行不得随意扩权访问未声明主机。
- 首版的本机 Runtime 同时需要连接平台和被测系统，平台失联后停止领取并按租约取消、清理。禁止为方便执行关闭域名约束。旧离线路径的被测系统可达条件仅用于历史兼容。
- 代理/证书配置须显式、可诊断，且不得削弱 TLS 校验作为默认。

### 17.7 检查清单

- [ ] 新出站有超时/重试/幂等说明
- [ ] 用户可控 URL 经 SSRF 防护
- [ ] 密钥不在仓与前端；适配器边界清晰
- [ ] 失败不放大为重试风暴
