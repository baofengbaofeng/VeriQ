# Coding standard

行宽口径：源码及注释每个物理行最多 **120 个显示列**，与 IDE 的 120 列标尺一致。
中文及其它全角/宽字符占 2 列，ASCII 占 1 列；缩进、标点和注释分隔符均计入。

本文是 VeriQ 仓库编码规范的入口。语言细则以专项指南为准；本文件只规定跨语言强制约定，以及与 VeriQ 产品约束冲突时的优先规则。

## 1. 格式与工具

- 缩进：可编程源码一律 **4 个空格**；禁止 Tab（`.editorconfig` 明确例外除外，如 `Makefile`）。
- 代码行和注释行都最多 **120 个显示列**。导入语句同样必须遵守此上限。Prettier 的 `printWidth: 120` 只是排版目标，硬上限由显示列宽检查器判定。
- 字符集与换行：UTF-8、LF、文件末换行；遵守仓库根 `.editorconfig`。
- Python：静态检查使用 pylint，并配合 pylintrc；格式化使用 Black 或 Pyink。风格细节遵循《Python 编码规范》。
- TypeScript/JavaScript：以 Biome / Prettier / `tsc` 为准；风格细节遵循《TypeScript/JavaScript 编码规范》。
- C/C++ 原生代码：4 空格；与所属平台 native 模块既有风格保持一致，新增文件不得引入 Tab。
- 禁止为「临时」或「占位」代码另立宽松格式标准。

### 1.1 显示列宽的统一计算

120 是物理行的显示列数，不是 Unicode 字符个数、UTF-8 字节数或 JavaScript UTF-16 长度。
与 IDE 中等宽字体的 120 列标尺采用同一口径：

- ASCII 和普通窄字符占 1 列；中文及 Unicode East Asian Width 为 W/F 的字符占 2 列。
- 组合附加符号（Mn/Me）与格式字符（Cf）不额外占列；模糊宽度 A 按 1 列。
- 行首缩进、标点、引号、注释分隔符都计入；换行符不计入。
- Tab 推进到下一个 4 列制表位，但不得用 Tab 绕过既有的空格缩进要求。
- `// ` 加 59 个汉字是 121 列，必须换行；60 个汉字正文恰好是 120 列。
- 代码、注释、docstring、导入语句和生成源码均适用，不能用禁用检查或转义中文来隐藏超限。

运行 `python3 scripts/line_width.py` 或 `pnpm lint:width` 检查全仓源码。
检查范围包括测试、夹具、构建脚本、原生代码和安装脚本；生成源码须修正生成器并重新生成。
Markdown 正文、数据 Schema、依赖锁文件和第三方依赖不属于此源码扫描范围。
这些文件中的源码示例仍须在编写和审查时遵守同一列宽口径。

Prettier、Black/Pyink、Ruff 的行宽参数只是排版目标，不能保证长注释和字符串符合显示列上限。
不得通过 IDE 自动软换行冒充源码已换行；超限必须在源码中实际断行。
注释可分行，代码应在合法语法边界断行；字符串须保持运行时内容，不能给 SQL、快照或模板引入换行。

注释首行的「至少 40 个字符」仍是有效正文的 Unicode 字符数要求，与显示列数分别计算。
必须同时满足正文长度与整行列宽；不得凑字、填空白或删除关键说明来满足机械检查。

## 2. 命名与标识

- 产品名人类可读形式为 **VeriQ**；技术标识保持小写：`veriq`、`@veriq/*`、`veriq_server`。
- Python：模块/包/函数用 `snake_case`；类用 `PascalCase`；常量用 `UPPER_SNAKE_CASE`（与 PY 指南一致）。
- TypeScript：遵循 TS 指南的命名约定；导出符号须可被公开 API 注释与契约生成覆盖。
- 数据库表：一律 `veriq_` 前缀；迁移版本表 `veriq_alembic_version`。
- 进程名：`veriq` / `veriq_agent` / `veriq_runner`（CLI 可 `veriq_cli`）须对应真实 OS 进程名。

## 3. 注释（中文）

- 源码注释（模块说明、公开 API 文档串、关键路径旁注）一律**中文**；产品名与技术标识可保留原文。
- 注释覆盖率必须 **> 40%**（注释行 / (注释行 + 非空代码行)）；仅排除生成物与 vendored 依赖。
- 每条注释解释**此处**职责、不变量、失败关闭点或非显而易见取舍；禁止套话灌水。
- 公开方法、公开类、公开接口/类型、导出函数必须有中文注释；核心分支与执行路径须覆盖。
- 每个注释块首行有效文字 **至少 40 个字符**且含中文；禁止空洞短标题与无信息填充。
- 每一行注释最多 **120 个显示列**，超出部分换行。注释行没有放宽上限的例外。
- 测试注释以行为说明为主，不要灌水。
- 机械检查：`scripts/comment_audit.py`（syntax-comments-v1）。自动通过不代替人工质量审查。

## 4. 日志（英文）

- logger、诊断 print、结构化 log event 的 message 字段必须使用**英文**。
- 请求体、领域数据、用户输入中的其它语言可以原样保留。
- 禁止在日志中输出密钥、token、Cookie、密码、完整凭证或未脱敏的隐私字段。

## 5. 错误处理与失败关闭

- 关键路径失败关闭（fail closed）：授权失败、租约/fencing 失效、停止证明不确定、签名校验失败等，不得「尽量继续」。
- 禁止宽泛 `except Exception` / `catch (e)` 后静默吞掉；若必须捕获，须记录英文日志并明确降级或失败语义。
- 不确定状态须进入隔离/人工恢复路径，不得伪造成功。

## 6. 生成物与不可变产物

- DSL 可编辑；由编译器生成的 TypeScript 等产物视为**不可变**，禁止手改后当作源码提交（除非任务明确是调整生成器并重新生成）。
- 契约生成文件（如 `*.generated.ts`）只能通过正式 generate 流程更新，并与 Schema/OpenAPI/样例一并提交。
- 前端生产静态资源经 stage 进入 `apps/srv/src/veriq_server/static/dist`；不得把密钥打进前端产物。

## 7. 依赖与复用

- 优先成熟第三方库；禁止自研密码学、浏览器等待、Cron、schema/迁移框架、通用报告引擎。
- 新增依赖须符合《依赖与许可规范》，并与锁定工程基线一致。

## 8. 检查清单（提交前）

- [ ] 缩进与 `.editorconfig` 一致
- [ ] 代码、导入与注释每个物理行均不超过 120 个显示列；显示列宽检查已运行
- [ ] 触及语言的 lint/format/typecheck 已通过
- [ ] 公开 API 与关键路径有合格中文注释；首行至少 40 个字符，每一行注释不超过 120 个显示列
- [ ] 日志为英文且无敏感信息
- [ ] 未手改不可变生成物；契约变更已重新生成
- [ ] 未引入与 PY/TS 指南或本总则冲突的风格例外
