# VeriQ 前端工作流

## 多方案先请用户选择

有两个或更多实质不同的可行方案时，先比较，再直接请用户选一项。保留用户提出的所有可行选项。
有明确约束使某项不可行时，说明依据。推荐某项、改动量较小或工期紧都不影响其它方案的可行性。

「两种都能接受」「都行」「请直接继续」和沉默都不构成选择。用户须明确选定一项。在此之前只做
只读调研和比较，暂缓修改文件或派发实现任务。
把选型确认作为其它通用技能和实施流程的前置步骤。当前环境只读时，照常比较并请用户选择。
需要写入权限时，等方案已定且实施获授权后再处理。

用简表逐项说明做法与关键取舍，给出一个推荐和理由。用直接的选择题结束本轮答复。以记录详情为例。

| 选项 | 做法 | 主要取舍 |
| --- | --- | --- |
| A | 在当前列表的抽屉中展示详情 | 保留列表上下文，详情可用空间随抽屉宽度变化 |
| B | 在独立页面展示详情 | 能容纳更多内容和直接链接，返回时需要恢复列表状态 |

推荐 A，因为这项工作需要在列表中来回核对记录。你选 A（抽屉）还是 B（独立页面）？

## 核对现状并准备方案

阅读仓库根 `AGENTS.md`、`README.md`、任务简报以及相关页面、组件、样式和测试。
通过规则及文档索引查找适用规范、契约与平台资料。
涉及依赖、桌面渲染边界或公共行为时核对相关 ADR。[规则索引][规则] · [文档索引][文档]

- 设计或评审界面时，读取字号、视口、布局、交互、本地化和权限规则。[界面规范][规范]
- 实现表单时，按字段的必填规则在标签文案左侧标红色星号，已有默认值的必填字段同样标记。10px 输入
  提示置于控件下方。[字段规范][字段]
- 列表工具栏中的搜索和筛选省略 `?` 帮助入口，下拉选值和选项字号与相邻文字一致。[字段规范][字段]
- 下拉菜单宽度随触发控件和选项内容调整，单行选项与收起的触发控件等高。鼠标悬停用轻微底色，
  键盘焦点用独立背景色。[下拉规范][字段]
- Web、Electron 和共享视图统一复用 `DataTable`，表身和页脚沿用 Data Table 3。页面、详情、对话框、
  编辑抽屉及消息中的表格都适用，保留原字号、空态和业务列。[数据表格规范][表格]
- 表格工具栏按 Basic Table 5 组织，左侧放每页数量，右侧依次放常显搜索、筛选、查看全部和下载。
  其他筛选条件集中在筛选入口，无业务筛选的表格省略该按钮。[表格工具栏规范][表格]
- 提交用蓝色按钮，删除用红色按钮。用户主动发起且需要等待的操作在同一个共享 Dialog 显示进度和
  最终结果，保持背景布局稳定。[操作规范][操作]
- Web 和桌面控件通常用背景色表示焦点和选中。普通输入框和文本域聚焦时保留 TailAdmin 默认底色，
  用自身品牌色边框提示焦点。Tabs 采用 Line Variant，横向页签以底部品牌色下划线标记当前项。
  省略额外的灰色外框或阴影描边。[焦点规范][字段]
- 选择组件时，按用户要完成的动作查索引。已有做法覆盖时，核对该条的 VeriQ 源码和本次调用。
  需要新适配或有疑问时，才打开对应的 TailAdmin React Free 固定提交源文件和许可证。
  [组件索引][组件]
- 规划验收或准备交付时，按受影响的真实入口选择 Web、组件或 Electron 验证。[验收指南][验收]

向用户说明改动范围、页面布局、可复用组件及其来源、关键交互、拟改动文件和验证方式。按实际任务
控制篇幅。调整已有方案时，只需说明本次影响。

- 仅有一条合理路径，或用户已明确选择且范围无实质变化时，实施已获授权即可在简要方案可见后推进。
  发现新的实质性取舍时，按上文比较并等待选择。
- 只要求方案、评估或设计调整意见时，在会话里交付，保持仓库只读。取得实施授权后再进入实现。

实现遵循根 `AGENTS.md` 的分工。交付时记录实际验证的界面、语言、视口、状态与交互，并注明因环境
或夹具缺失未能核验的项目。
